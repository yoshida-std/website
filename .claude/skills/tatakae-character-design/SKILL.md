# 戦え！ゆうしゃ キャラクターデザイン

ゲームのキャラは、**直方体(箱)だけを組み合わせたローポリのモデル**です。テクスチャも曲面もありません。デザインは「箱で作れる形」に落とし込めることが最優先です。この前提を外した絵を作っても、ゲームには入りません。

## 最初に読むもの

- ゲームの決まりごと(操作・数値・作業の進め方): `games/Tatakae-Yusha/CLAUDE.md`
- 今のキャラの数値(高さ・色・部品数): [references/characters.md](references/characters.md)
- 箱モデルのコードの書き方: [references/model-format.md](references/model-format.md)
- 画像生成AIに渡す指示(貼れる文面): [references/prompt-template.md](references/prompt-template.md)

## 作業のモード

依頼を読んで、どれかを選びます(複数のこともあります)。

| モード | 依頼の例 | 成果物 |
|---|---|---|
| A. デザイン案・依頼書づくり | 「新しい敵を考えて」「AIに頼む指示を作って」 | デザイン仕様書(下の「仕様書の書式」)と、画像AI用プロンプト |
| B. 絵 → 箱モデル | 「添付のデザインに変えて」 | `render2d.js` のモデル関数、三面図、差分メモ |
| C. 既存キャラの調整 | 「大きさを勇者に合わせて」「色を変えて」 | 変更したコード、更新した三面図 |

## 進め方

### 1. 依頼を整理する(聞くのは、決められないことだけ)

次の項目が決まっているか確認します。足りなければ、**標準の値で決めて**「この前提で進めます」と伝えます。聞きすぎて止まらないこと。

- 役割: 味方(パーティ)か、敵か、ボスか。ゲームの中での強さ・大きさのイメージ。
- 大きさ: 勇者(高さ 2.17)を基準にした比。標準は「味方=勇者と同じ高さ」「敵=勇者の1.4〜1.7倍」。
- 色: 使う色の数(標準は12色以内)。色コード(`#rrggbb`)があるか。
- 世界観: ドラクエ風のファンタジーだが、**既存の名前・キャラ・デザインは使わない**(オリジナルにする)。
- 動かす予定: 歩く・剣をふる・倒れる・勝利ポーズなど。

### 2. 箱で作れるか確認する(絵が来たとき)

絵を見たら、箱モデルにできない点を先に洗い出し、**どう置きかえるか**を決めて伝えます。

| 絵にあるもの | 箱モデルでの置きかえ |
|---|---|
| 曲面・丸い髪・ふくらみ | 小さな箱を段にして重ねる。丸みは色の面で表す |
| 斜めの面・とがり | 箱を回転(`ops` の `z` 回転など)して作る。とがりは細い箱を重ねる |
| ひじ・ひざの曲げ | なし(腕・脚は1本の箱)。動きは肩・ももの付け根の回転だけ |
| ひらひらした布・マント | 薄い箱を後ろに数枚。ゆれは `t` に合わせた回転で表す |
| 細かい模様・刺しゅう | 色の細い箱(厚さ 0.015〜0.03)を表面にはる(`bias` でちらつきを防ぐ) |
| 目・口 | 顔の前面に、薄い箱(厚さ 0.02)を置く |
| 半透明・光・影 | 使わない(エフェクトは別の仕組み) |

### 3. 箱モデルを作る(モード B・C)

[references/model-format.md](references/model-format.md) のとおりに、`games/Tatakae-Yusha/src/render2d.js` へ、`xxxParts(...)` の形で書きます。守ること:

- 部品は **80個以内**(描画側の上限 `BoxModel(80)`)。標準は 60〜70個。
- 原点は足もとの中心。前は `+z`、上は `+y`。
- 足は先に作る(体をかたむける動きで、足だけ動かさないため)。
- 見た目の大きさは **`scale` で調整し、当たり判定(`CFG` の `r`)は変えない**(変えるのは別の依頼のとき)。
- 色は `#rrggbb` の12色前後。色の定数は関数の先頭にまとめる。

### 4. 確かめる

1. `node tools/sansmen.js <キャラ名>` で**三面図**を作り、元の絵と見比べる(差を言葉にして報告する)。
   - ツールがまだ対応していない新キャラは、`tools/sansmen.js` の `WHO` と設定(`CF`)に足す。
2. 高さ・頭の大きさ・部品数を測る(`references/characters.md` の測り方)。**勇者と同じものさしで並べて**比べる。
3. ボット(`tools/bot.js`)で、ゲームが最後まで動いて、エラーが出ないことを確認する(**2D表示との比較はしない**。開発は WebGL だけで進める)。
4. ゲーム内で見える大きさ(スマホ縦画面の幅 390px)で、見分けがつくか見る。
5. ゲームの変更は **Artifact で見てもらい、OK をもらってからプッシュ**(リポジトリのルール)。

### 5. 書いておく

- `games/Tatakae-Yusha/CLAUDE.md` に、デザインの決め事(大きさの倍率、色、部品の構成)を書く。
- 三面図(`docs/<キャラ>-3view.png`)をコミットする。

## 仕様書の書式(モード A の成果物)

```
## キャラ名(仮)/ 役割
- 一言: どんなキャラか(1〜2文)
- 大きさ: 高さ ○○(勇者=2.17 に対して ○倍)/ 頭の高さ:全身 = 1:○ / かたはば ○○
- 当たり判定の半径: ○○(今のキャラと比べて)
- 特徴(固定): 見分けのつく3〜5点(つの・リボン・色 など)
- 色(12色以内): 名前・色コード・使う場所の表
- 動き: 待機・歩き・攻撃の予告・攻撃・やられ・勝ち のうち必要なもの
- 箱の構成の目安: あたま○個・からだ○個・うで○個・足○個・もちもの○個(合計 80個以内)
- 画像AIに頼むプロンプト: (references/prompt-template.md をもとに)
```

## 画像生成AIに頼むときの要点

くわしい文面は [references/prompt-template.md](references/prompt-template.md)。要点だけ:

- **先に三面図**(正面・側面・背面。同じ高さ・同じ縮尺。パースなし)。ポーズ集は、三面図ができてから「同じ造形で」と頼む。
- 箱(ボクセル)だけで構成、曲面・斜めの面は使わない。腕・脚はまっすぐな棒状。
- 色は12色以内で、色コードは**別の文章で**もらう(画像の中の文字は崩れやすい。絵に文字を入れない)。
- 比率は数字で(「勇者を高さ100として、この子は○○」「頭は全身の1/○」)。
- 今の三面図(`docs/*-3view.png`)を参考画像として渡し、「この比率・この箱の数を保って、デザインだけ変えて」と頼む。

## やってはいけないこと

- ゲームのロジック・数値(`CFG` の `hp` `speed` `r` など)を、見た目の依頼で変えない。変えたい理由があれば、先に相談する。
- ドラゴンクエストなど、既存の作品の名前・キャラ・デザインをそのまま使わない。
- 80個を超える部品、曲面、テクスチャ、半透明を前提にしない。
- 説明のない絵(文字入りで読めない・色コードが崩れている)を、そのまま仕様として扱わない。色は絵から読み取り、**読み取った値を表にして**確認する。
- コミット・プッシュの前に、確認の手順を飛ばさない(`games/` の変更は Artifact で確認してからプッシュ)。
