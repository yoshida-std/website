## 1. 一行要約

戦闘フィールド上で、敵と味方が体(円)をぶつけ合い、「重さ」が大きい側が相手を押し込める。前衛が敵を後衛から引き離す=MMORPGの「ヘイト管理(タンク)」を、位置取りで視覚的に表現した仕組み。 [記載]

| 用語 | 意味 |
|---|---|
| 移動干渉 | 正式名称。キャラ同士が移動中にぶつかり、押す・押される関係になること [記載] |

## 3. 登場要素(エンティティ)

### 3.1 戦闘キャラクター(敵・味方共通)
- 位置(x, y)と**円形の当たり判定**を持つ。座標は円で近似されている [記載]
- ステータス「重さ」を持つ [記載]
- 敵は「ターゲット(狙う味方)」に向かって移動する。到達すると攻撃できる [記載(間接)]

### 3.2 味方パーティ
- 最大4人(本作の標準。本仕様書の出典には人数の明記なし → [不明]だが一般知識として4人)
- 押している味方が複数いれば**重さが合計される** [記載]

### 3.3 戦闘エリア
- 自由に動き回れる範囲。境界の外に出るとその側が戦闘離脱扱い [記載]
- 敵を押し出して倒す/勝つ仕組みは**ない**。(他作品の「土俵押し出し勝ち」とは別物) [記載]

## 4. 中核ルール

### 4.1 重さの基本原理 [記載]
1. 重さが大きい側が相手を押せる
2. 差が大きいほど、速く押し込める
3. 差が小さい(拮抗)と押し合いになる
4. 味方は「押している人数分の重さの合計」で比較される
5. 立っているだけでも重さは効くが、相手に向かって押すとより効果的になる

### 4.2 押し合いの再現モデル [推測]
実数式は非公開。設計検討用に、次の簡易モデルで置き換えて考える。

```
# 双方の合計重さ
W_ally  = Σ weight(押している味方)
W_enemy = weight(敵)

# 押し込み速度(再現モデル。実ゲームの式ではない)
push_speed = k * (W_ally - W_enemy)      # 正なら敵が後退、負なら味方が後退
|diff| が小さいとき → 拮抗(ほぼ停止)
```

- `k`(押し込みの強さ係数)と、押し込みの上限速度は [不明]
- 「立っているだけ」と「押している」の重さ効果の差(倍率)は [不明]

### 4.3 ターンエンドと押し合い反撃 [記載]
- 同じ相手を**15秒以上**押し続けると「ターンエンド」になる
- ターンエンド後、敵が押し合い反撃を行う
- 反撃を受けた後も押し続けると、**即座に再び反撃される**
- 反撃後はしばらく押すのをやめて様子を見るのが定石

意図(推測): 「押し続ければ永久に敵を封じ込められる」状態を禁じる、ゲームバランス上のブレーキ。通常の戦闘ターン進行との関係(反撃の威力・範囲など)は [不明]。

### 4.4 戦闘エリア外に出た場合 [記載]
| 状況 | 結果 |
|---|---|
| 自分が押しすぎて自分が戦闘エリアの外に出る | 「逃げた」扱いで戦闘終了(逃走可能な雑魚戦で注意) |
| 味方が押し負けて外に出される | 戦闘終了(めったに起きない) |
| 敵を押し出す | **起きない**(敵が外に出ることはない) |

### 4.5 重さを増やす手段
| 手段 | 内容 | 信頼度 |
|---|---|---|
| 装備 | 重い鎧・盾・ハンマーで「おもさ」ステータスを上げる | [記載] |
| ヘヴィチャージ | パラディン専用特技。はくあいスキルのランク7で習得。消費MP4。強化系。**90秒間**、自分の重さを増加させる | [記載] |
| 重さの倍率 | ヘヴィチャージで重さが**2.5倍**になるとする攻略記事がある | [記載(攻略サイト1件のみ。要検証)] |
| 人数 | 複数人で同じ敵を押すと合計される | [記載] |

補足: 「必要な重さが分かるなら、それ以上は不要。ただし正確な必要値の把握は難しい」とされ、パラディンは重さを最優先で盛るのが定石。 [記載]

## 5. 役割と戦術(ゲームデザイン上の使われ方)

| 戦術 | 内容 | 信頼度 |
|---|---|---|
| 壁(基本形) | ヘヴィチャージをかけたパラディンが敵を押し、後衛の魔法使い・僧侶へ攻撃が届かないようにする。後衛は後ろから魔法で攻撃 | [記載] |
| 拮抗維持 | 敵の範囲攻撃(超暴走魔法陣など)に当たらないギリギリの距離で押し合いを維持する。壁まで押し切らない | [記載] |
| 陣へ押し留める | 味方がジバルンバや災禍の陣を置いたエリアに、敵を押さえ込む | [記載] |
| 陣から押し出す | 敵が置いた陣から敵を押し出す | [記載] |
| 足止めだけ | パラディン・戦士がいない編成では押し勝てないが、敵がターゲットに到達するのを遅らせるだけでも被攻撃回数を減らせる | [記載] |

職業の位置づけ: 押し勝つ役はパラディンと戦士。パラディンは「ヘイト(敵対心)を上げる」ではなく**「敵を押して引き離す」ことでタンクをする**職業。 [記載]

## 6. 既知の問題・落とし穴

| 問題 | 内容 | 信頼度 |
|---|---|---|
| 誤って押し続ける | コマンド入力後の移動は敵へ直進するだけ。間に別の敵がいると延々押し続けてターンエンドになる。「エモノ呼び」などで敵が多いと起きやすい | [記載] |
| 大型敵とAI | 初期(Ver.1.0)は大型敵(怪蟲アラグネ等)に干渉されたAI味方が避けず、押し続けて蘇生に行けず全滅しやすかった。現在はAI改善済みだが、大型相手では干渉されやすい | [記載] |
| 壁抜け | Ver.6.4のサーバー機器交換後、壁があるのに敵がすり抜ける不具合が報告された。判定処理の変化が原因と推測され、Ver.6.5後期で仕組みの調整が予定されていた | [記載] |
| 押し合い開始の一瞬の硬直 | サーバー側計算への切り替えによる | [記載] |
| 押し合い中の不自然な動き | 座標のずれを運営がこっそり補正しているため | [記載] |

## 7. 実装上の仕組み(オンラインゲーム特有)

新しいソロゲームでは**大部分が不要**。ただし「なぜ今の形なのか」を理解する材料として残す。 [記載]

- 最大の技術課題は、押し合う2体の**モデル(体)の座標を一致させる**こと
- MMORPGはクライアント優先で動くため、他キャラや敵の位置は必ず遅れる
- そのため**押し合いの間だけ、座標計算を完全にサーバー側へ委ねる**
- 押し合い中はサーバー負荷が高いため、戦闘は専用プロセスに分離。座標は円で近似して負荷を軽減
- **ソロ・オフラインなら**: 同期問題はなく、物理演算を1つのループで素直に書ける(=現行の技術的制約は外せる)

## 8. 設計上の特徴(評価されている点)

[記載]
- ヘイト管理を、「前衛が敵を後衛から引き離す」という**目で見て分かる形**にした
- 自由に動ける戦闘エリアで立ち回る理由が生まれ、棒立ちを防ぐ
- 大きな説明なしでプレイヤー間に浸透した(直感的)

## 9. 現行システムの状態遷移(再現モデル) [推測]

```
[接触前] --(敵・味方の円が重なる)--> [押し合い中]

[押し合い中]
  ├ W_ally >> W_enemy → 敵が後退
  ├ W_ally ≈ W_enemy  → 拮抗(足止め)
  ├ W_ally << W_enemy → 味方が後退(エリア外なら戦闘終了)
  └ 押し続けて15秒経過 → [ターンエンド] → 押し合い反撃 → [押し合い中(再押しで即反撃)]

[押し合い中] --(自分がエリア外へ)--> [戦闘終了(逃げた扱い)]
```

## 11. 新システム設計への入力(論点) 

現行の特徴を踏まえ、新設計で決めるべき軸の例。**これは提案であって現行仕様ではない。**

1. **勝利条件との関係**: 現行は「押し出しても勝てない」。新システムで押し出しを勝敗に結びつけるか
2. **ソロ向けの再設計**: 現行は「パーティ内の役割分担(壁と後衛)」が核。ソロでは1人で何を押し、何を守るのか
3. **重さの入手手段**: 装備・スキル・人数合算のうち、何を残すか
4. **ブレーキ機構**: 15秒ターンエンドの代わりに、どんな「押しっぱなし防止」を置くか
5. **操作系**: 現行の「移動入力=押す」を踏襲するか、専用ボタンを設けるか(スマホ縦持ち等の操作条件)
6. **視認性**: 押し合いの優劣をプレイヤーにどう見せるか(現行は説明なしで伝わった点が強み)
