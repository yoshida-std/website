## 1. コンセプト

> **コマンドで「何をするか」を決め、相撲で「それが通るか」を決める。**

- コマンドバトル(ドラクエ)の「選ぶ楽しさ」と、相撲(位置取り)の「阻む・かわす楽しさ」を1ターンの中で連動させる
- 敵は「行動の予告」を持ち、そこへたどり着けば行動できる。**壁役が敵を阻み、届かなければ行動は空振りになる**(これがDQ10の「後衛を守る」の本質)【継承】
- 勝利はHPで決まる。相撲は勝敗を直接決めず、被害を減らす・味方に時間を与えるための仕組み

## 2. 勝敗とHP

- 勝利: 敵全員のHPを0にする。敗北: 味方全員のHPが0
- 押し出しは勝利につながらない。敵は戦闘エリアの外に出ない(現行DQ10と同じ)【継承】
- 相撲の成果は次の形でHPに現れる:
  - 敵の攻撃が**空振り**(届かない)→ 被ダメージ減
  - 後衛の**詠唱が通る**(攻撃・回復呪文の成功)→ 与ダメ・回復増
  - 敵の背後・側面からの攻撃に**ボーナス**(§7)→ 与ダメ増
  - 敵を障害物に押し付ける**壁ドン**→ よろけ(行動遅延)とダメージ(勝利条件ではなく戦術効果)

## 3. コマンドと相撲の組み合わせ(3案と推奨)

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. DQ10式(アクティブ) | 常にリアルタイム。コマンドは歩きながら選ぶ | 現行に近い。緊張感が高い | スマホでは「コマンド選択」と「移動操作」が同時に必要で、指が足りない |
| **B. ターン実行型(推奨)** | ①コマンド選択(時間停止)→②実行フェーズ(約12秒・リアルタイムで立ち回り)→③結果 | 指の負担が少なく、考える時間もある。ドラクエらしさを保てる。相撲が「ターンの中の見せ場」になる | 実行中にプレイヤーができる操作を絞る設計が必要 |
| C. 完全リアルタイム | 専用ボタンで技を出す(アクション) | 手軽 | ドラクエのコマンドバトルの味が消える |

→ **B案を採用**。DQ10でも「ターン」と「15秒で反撃」の概念があり、素直に移せる【継承の発想】。

### 3.1 1ターンの流れ(B案)

```
[1. 予告]   敵が「だれを狙うか」と「何をするか」を決め、頭上に表示(ドラクエの敵名表示のように)
[2. コマンド選択]  時間停止。各キャラのコマンドを選ぶ
     たたかう / とくぎ / じゅもん / どうぐ / ぼうぎょ / (主人公のみ)かまえ
[3. 実行フェーズ]  リアルタイム約12秒【仮】
     ・敵:狙う相手へ移動 → 射程に届けば予告した行動を実行
     ・味方:コマンドを実行する位置へ自動移動(主人公だけ指で操作可能)
     ・主人公(壁役):敵と味方の間に入り、押す・止める・回り込む(§5〜§7)
[4. ターンエンド]  時間切れ。未実行の敵行動は空振り。押し合い反撃の判定
[5. 結果]  被害・回復・状態異常を反映して次のターンへ
```

- 実行フェーズの長さは現行の15秒より短縮して12秒【仮】。1戦=5〜8ターン程度で、**1戦2〜4分**【仮】
- 実行フェーズ中は、指1本で主人公の位置と構え(§5.2)だけを操作する。他のキャラは自動

## 4. 画面とカメラ(縦画面・3D風)

### 4.1 「3D風」の方針
- **ロジックは平面(x, z)の円**。描画だけを透視投影して奥行きを見せる(§13)
- カメラは主人公の背後やや上から、ロックオンした敵を向く。**縦画面は奥行きが長く見える**ため、前進=敵へ近づく、が直感的
- 敵・味方は、最初はキャラの絵(板ポリ/スプライト)を立てる形でよい。3Dモデルは必須でない
- **視野は「ひろい」に決定(2026-11-21)。切りかえはやめた**。(以前は3段階から選べるようにしていた)【プロトタイプで追加】。カメラの引き・高さ・画角を変える。初期値は「ふつう」。プロトタイプ実機確認で「せまい」では後衛が画面下のウィンドウに隠れ、視野が狭く感じたため。縦画面では、後衛(守る対象)が常に見えることが重要
- **背景のイメージ(ユーザー提供の参考画像 2026-11-21)**: 夜空(星・星座の線)、遠くのアーチ状の遺跡の壁と塔、たいまつの灯り、青灰色の石だたみの地面、金色の縁の円形闘技場。プロトタイプでは画像を使わず、Canvasの描画で再現した(視点を回すと遠景がずれて動く)。場外の目じるしは金色の縁線。本番では画像素材に差し替える想定
- **ゆうしゃの見た目(ユーザー指示 2026-11-21「後ろ向きのみ、本物に近い仕上げ」)**: 後ろ向きだけを、ふちどり・グラデーション付きのベクター画で描く。青いツンツン髪と金のヘアバンド、赤いマフラー、肩あて、金のふちのマント(ゆれる)、左うでの盾、右手の剣、革のブーツ。歩くと足が交互に上がり上体がゆれる。剣を振るとフリックの向きに剣が動き(横=ふる、縦=ふり下ろす)、軌跡と合わせて見える。ふれたとき白く光る。本番では画像素材(スプライト)への差し替えを想定。後衛・敵は仮の四角いまま
- **ゆうしゃはローポリ3Dモデル(ユーザー指示 2026-11-21「ドラクエすぎるので見直し。3Dにできないか」)**: 4方向の2D絵をやめ、箱を組みあわせた約60パーツのモデルを、自前の3D計算(回転・裏面カット・面の明るさ・奥行き順の描画・黒い輪郭線)でCanvasに描く。ライブラリ不要。向きは連続した角度(yaw)で、動いた方向へなめらかに回る(旋回速度16rad/s)。止まって0.3秒でロックした敵のほう(うしろ向き)に戻る。フリックの剣ふりは振った向きを0.35秒向く。デザインはドラクエ風を避けた**オリジナル案「力士の戦士」**: ちょんまげ(赤いひも)・白いはちまき(赤い丸)・ティール色のベスト・紫のまわしふうの帯と前だれ・鉄のこて・広刃の剣・わらじ。剣ふりは、横(フリック方向に合わせて腕を回す)と縦(振り下ろし)で動きが変わる。歩くと足とうでが交互に振れ、帯の後ろ結びがゆれる。**まほうつかい(星のぼうし・紫のローブ・光るつえ)と敵(つの・まわし・どっしりした体の「どすこいオーガ」。予告中は両手をふりあげ、よろけで体がゆれ、とっしんで前かがみ)も同じ方式のローポリ3Dに更新(2026-11-21)。向きはねらう相手のほうを向く。**本番はglTFモデルを使い、3Dシーン全体はWebGL(Three.js等)にする想定
- **ゆうしゃの足もとは、画面のたて半分あたり(上から50%)に固定する**(ユーザー指示 2026-11-21)。視野を変えても同じ位置になるよう、地平線の位置をカメラの高さ・引きから計算して決める。「ひろい」のカメラ高さは7.0→5.2に下げた【仮】

### 4.2 縦画面レイアウト【仮】
```
┌──────────────┐
│ 敵の名前・HP・予告  │ ← 上部(読むだけ)
│                  │
│   3D風フィールド    │ ← 中央(ここを見る)
│                  │
├──────────────┤
│ パーティHP/MP窓    │
│ コマンドウィンドウ  │ ← 下部(親指が届く。ドラクエ風の枠)
└──────────────┘
```
- 上部の設定ウィンドウ(プロトタイプでは敵の重さ・視野・フリック感度など)は、右上の小さなボタン(▲/▼)で**隠す/開く**ことができる。状態は保存する(ユーザー指示 2026-11-21)。隠すと画面の上が広く使える
- コマンド選択中は下部にメニュー。**実行フェーズ中はメニューが縮み、画面全体がドラッグ操作領域になる**
- 文字は大きく。長い説明文は出さない(縦画面は情報量が少ない)

## 5. 操作

### 5.1 コマンド選択フェーズ(時間停止)
- ドラクエ風のコマンドウィンドウ。タップで選択。親指が届く下部に配置
- 敵の予告(だれを・何を)を見て、「ぼうぎょ」「かばう」「陣形」などで対策できる

### 5.2 実行フェーズ(リアルタイム・指1本)
**ロックオン式**: 操作は常にロックオンした敵を基準にした相対操作とする。

| 指の動き | 動作 |
|---|---|
| 上へドラッグ | 敵へ前進(=**押す**) |
| 左右へドラッグ | 敵を中心に**回り込む**(円運動)。回り込みを直感的にするための設計 |
| 下へドラッグ | 後退 |
| 触れたまま止める / 離す | **踏ん張る**(重さ増・粘りが回復) |
| 素早い**フリック**(向きは問わない) | **剣を振る**(ユーザー決定)。**画面上で敵に重ねたフリックは、その敵を攻撃する**(遠くても踏み込んで当てる)。敵に重ならないフリックは、正面の範囲の敵(なければロック中の敵)に当たる。背後からは1.3倍。**敵の「！」の最後の0.4秒(「いま！」)のフリックは「いなす」**(成功で敵がよろけて弾き飛ばされる。振った直後0.5秒はいなせない) |

- 「フリック(剣を振る/いなす)」と「移動(ドラッグ)」の区別:
  - **敵のキャラクターに重なって始めた操作は移動にならない**(ユーザー決定)。その操作はフリック(攻撃)かタップ(ロック)にだけ反応する。敵の重ならない場所から始めた操作が移動になる。敵に重ねた操作中は黄色の輪で敵を強調する
  - フリックの判定: 直近0.12秒の動きが、横・斜めは一定以上の速さ、縦(縦成分が横の1.6倍超)は少し厳しめの速さを超えたときフリックとする。感度は3段階(びんかん/ふつう/にぶめ)で選べる【仮: ふつう=横450・縦900px/秒、距離36px以上】
  - 敵の狙い方: ①操作を始めた位置が敵に重なっていればその敵 ②なければ、なぞった線が通った敵 ③どれにも重ならなければ正面の範囲の敵(なければロック中の敵に踏み込む)
  - 敵の判定範囲は、画面に描いた敵の大きさ+14px(指で当てやすくするため)【仮】
  - 検証ポイント: 敵に囲まれて移動の指を置く場所がなくなる状況がないか、敵に重ねたつもりの移動が誤判定にならないか
- フリックの直後0.25秒は、その場に踏みとどまる(移動入力を無視)。フリックの連続は0.2秒あけて検出する。剣を振る間隔は0.35秒。フリック判定から0.06秒かけて指の最高速を測り、強さを決める。振る間隔の最中のフリックは0.32秒だけ溜めておく【仮】
- **ゆうしゃは何も操作しなくてもダメージを与えられない**(ユーザー決定)。攻撃は必ずフリックで行う
- **ふりまくりの対策(ユーザー指摘 2026-11-21「剣を振りまくるだけで勝ててつまらない」)**。原因は、いなすの判定が「予告中の直近0.2秒にフリックがあれば成功」だったため、振りまくると**全部の攻撃が自動でいなされ**、よろけた敵を叩き続けられたこと。次の3点で直した【数値は仮】:
  1. **いなすはタイミング制**: 敵の「！」の**最後の0.4秒**(画面では水色の「いま！」に変わる)に打ったフリックだけが成功する。それより早いフリックは通常の攻撃になる
  2. **振った直後0.5秒は、いなせない**(ふりまくり防止)。攻撃と防御の切り替えに隙ができる
  3. **剣のきりょく**: 剣を振るたびに14〜26(速く強いほど多い)消費。最大100、毎秒18回復。0になると「いきぎれ」で、40に戻るまで振れない(いなすは可能)。ゆうしゃの頭上の青いゲージで見える
  - 攻撃の見返り: **よろけている敵(いなした後、とっしんの後)へは2.2倍**。ねらい目を作り、「いなす→スキに叩き込む」を基本の流れにする
  - ボットでの確認: 「何も考えずフリックし続ける」と15〜17秒でゆうしゃが倒れる(敵は半分以上残る)。「いなして、スキに攻撃する」と勝てる
- **「おす」を続けている間は剣を振れない**(ユーザー指示 2026-11-21)。上ドラッグの「おす」状態が0.3秒【仮】以上続いている間のフリックは、攻撃として扱わず「おしている間は ふれない！」と表示する。**「いなす」は押している間もできる**。攻撃するには、押すのをやめて(踏ん張る・回り込むなど)からフリックする。押し続けて粘りゲージを溜める行動と、攻撃との間に選択を作るための制限
- **ダメージはフリックの仕方で変わる**(ユーザー決定。数値は【仮】): 基本ダメージ8 × 速さ倍率 × 向き倍率 × 背後1.3
  - 速さ倍率 = clamp(0.6 + 最高速[px/秒]/1500, 0.8, 2.0)。1.45以上で「つよい！」、1.8以上で「かいしん！」(画面が揺れる)、1.0未満で「かるい」と表示
  - 向き倍率: 横=1.0 / 斜め=1.15(「ななめぎり」) / 縦=1.3(「たてぎり」。判定が厳しいぶん高い)
  - ダメージ数字は**黄色**(ゆうしゃ)。まほうつかいは紫で区別する
- 画面にフリックの軌跡(青白い線)と、フリック認識時の輪、フリックした向きの剣の軌跡を出し、反応が見えるようにする
- 敵が複数いる場合、ロックオンの切り替えは敵をタップ(実行フェーズ中でも可)

## 6. 相撲の力学(重さ・構え・粘り)

### 6.1 有効重さ
```
W_eff = weight × stance_mult × terrain_mult × angle_mult
```
| 係数 | 内容 | 初期値【仮】 |
|---|---|---|
| stance_mult | 押す1.2 / 踏ん張る1.6 / いなす0.6 / 通常1.0 | 同左 |
| terrain_mult | 氷0.6、砂1.0、泥1.3、上り坂1.2・下り坂0.8 | 同左 |
| angle_mult | 正面1.0、側面0.7、背面0.5 | 同左 |

重さが大きい側が押し込む。比率 R=W_player/W_enemy に応じ、押し勝ち(R≧1.25)/拮抗(1.00〜1.25)/押し負け(0.75〜1.00)/突破(<0.75)の4段階で移動を決める(閾値は別AI資料の例に由来する未検証案。config化して調整)。

### 6.2 構えの読み合い(三すくみ)
押す > いなす > 踏ん張る > 押す(左が右に強い)。敵の構えは予兆(体の傾き・色)で0.4〜0.8秒前に分かる【仮】。

### 6.3 粘りゲージ(15秒ターンエンドの再設計)
- 「押す」で粘りが毎秒+7、「踏ん張る」で-5【仮】。満タンで敵が**押し合い反撃**(壁役への反撃。予兆つき)
- 対処は「踏ん張る(被害小)」「いなす(成功で無傷+カウンター)」「離脱(後退してリセット)」
- 反撃直後に押し続けると即再反撃【継承】。**実行フェーズが12秒なので、ゲージは1ターン内でほぼ満タンになる**【仮】

## 7. 回り込み(側面・背面)

敵に**向き(facing)**を持たせ、位置関係で効果が変わる。

| 位置 | 効果【仮】 |
|---|---|
| 正面 | 敵の攻撃範囲(前方扇形)に入る。押し合いが成立する |
| 側面 | 押す力が弱まる(0.7倍)が、敵の前方攻撃を受けにくい。後衛の呪文が安全に通る |
| 背面 | 与ダメージ+30%(背面攻撃ボーナス)。ただし重さ0.5倍で押し負けやすい |

- **敵の向きは、狙っている相手の方を向く**。つまり主人公が敵の注意を引いている間に、味方(後衛)が回り込んで背後から撃てる
- 範囲技・ブレス・呪文は壁では止められない。**射線(扇形)から外れる**ことで避ける(回り込みの価値)

## 8. 敵の行動と相撲の関係

| 敵の行動タイプ | 壁役で止められるか | 対処 |
|---|---|---|
| 近接単体攻撃 | 止められる(届かなければ空振り) | 押す・踏ん張って阻む |
| 近接範囲攻撃 | 一部止められる | 拮抗維持で距離を取る(DQ10の戦術を継承) |
| ブレス・呪文(遠距離) | 止められない | 射線から外れる、ぼうぎょ、かばう |
| 突進 | 構えの読み合い(予兆でいなせる) | いなして軸をずらす |
| 大型・重量級 | 押し勝てない | いなす・誘導・地形利用。押し続けると反撃を受ける |

### 8.1 敵のターゲット(ユーザー決定+プロトタイプとの差)

> **2026-11-21 変更(ユーザー指示)**: 敵のターゲット表示(頭上の「A▶まほう」・ねらい線・「ねらわれた！」の文字・下の窓の「▶ゆうしゃ」)はやめた。ターゲットの仕組みは そのまま動く。「てきが せまってくる」の表示もやめた。

**本番の仕様(ユーザー決定)**
- 敵は**ターゲットを持たない時もある**(「ターゲットなし」状態)。この間は予告を出さず、待機・周囲の警戒などをする
- **攻撃を加えた相手が、ターゲットになりやすくなる**(攻撃した者にヘイトが貯まる形)
- ターゲットは「ランダムな切り替え」ではなく、**プレイヤー(と味方)の行動の結果として決まる**。これにより、前衛が敵の注意を引き、後衛が安全に攻撃できる、という構図ができる

**ヘイトの仕様(ユーザー決定 2026-11-21)**
- **押し合いもヘイトを貯める**。ただし**攻撃のほうが優先される**(同じ時間で比べると、攻撃のほうがヘイトが多く貯まる)
- この決定により、壁役は「押して、さらに攻撃もする」ことで敵の注意を引き続けられる。後衛の遠距離攻撃は、距離があってもヘイトを貯めるため、後衛が狙われる場面も起きる。そこで壁役の**物理的な足止め(押し合い)**が役に立つ

**プロトタイプでの実装(数値はすべて【仮】)**
- 敵は最初**ターゲットなし**で、**土俵をうろうろ歩く**(ユーザー決定。ときどき立ち止まり、通常速度の4割で歩く)。ヘイトが一定値(8)に達した相手を狙い始める。ヘイトが両方とも一定値(3)を下回ると、**ターゲットなし**に戻る(狙いを見失う)
- ヘイトは毎秒1.5に加えて、**溜まっている量の18%ずつ**減る(2026-11-21変更。多く溜めた人も、攻撃をやめると素早く下がるので、一度ゆうしゃに決まると変わらない状態を防ぐ)
- 貯まり方: 押し合いで接触中は、「押す」で毎秒+2、それ以外の接触で毎秒+0.8(ユーザー指示で少なめに設定。自然に減る量が1.5なので、押し合いだけでは貯まりにくく、攻撃が主なヘイトの源になる)。攻撃のヘイトは、ゆうしゃがダメージの2倍、**まほうつかいは4.5倍**(魔法はヘイトが高い。2026-11-21変更。まほうつかい8ダメージ→+36)。攻撃の頻度はゆうしゃのほうが多いので、倍率で釣り合わせて、まほうつかいも狙われるようにした
- 狙いの切り替え: 現在のターゲットのヘイトを、別の相手が1.15倍以上上回り(1.25から変更)、かつ一定値(8)以上のとき(頻繁な切り替わりを防ぐ余裕)
- ゆうしゃの攻撃は**フリックで剣を振る**(自動攻撃はなし)。敵に重ねたフリックはその敵を攻撃(最大「接触から4.6」先まで踏み込む)。重ならない場合は正面の範囲(接触から2.2以内)の敵に当たる。ダメージはフリックの速さと向きで変わる(§5)。背後からは1.3倍。まほうつかいは、離れた場所から自動で魔法を撃つ
- まほうつかいの魔法: ダメージ8、発動間隔2.2秒(7、3.0秒から増強。ユーザー指摘「魔法使いの攻撃が少なく、ターゲットが魔法使いに移らない」)。ボットで、ゆうしゃが1.2秒に1回振る場合の狙われ先は、ゆうしゃ46%/まほう48%に釣り合った(以前はゆうしゃ84%/まほう1%)
- 敵にHPを設定し、**敵を全員倒すと勝利**(勝利条件は押し出しではなくHP)

**まだ決まっていないこと**
1. うろうろ歩く範囲や頻度(気づく距離は下記で実装済み。ユーザー指示 2026-11-21: **ターゲットなしの敵は、範囲(7.5【仮】)に入った味方をターゲットにする**。範囲内にいる間はヘイトが一定以上に保たれ、狙いを失わない。両方いるときは近いほうが少し高い。範囲の外へ出てヘイトが自然に減ると、ターゲットなしに戻る)
2. 回復・補助のヘイト(回復した人にヘイトが貯まるか)
3. ヘイトの上限や、倒れた味方・離脱した相手の扱い
4. 敵が複数いるとき、ターゲットを共有するか(現状は敵ごとに独立)
5. 押し合いのヘイト量と攻撃のヘイト量の比率(「攻撃が優先」のバランス。実機で調整)
6. 敵の「ねらい」の見せ方(現状は頭上に「A▶まほう」「A▶なし」と、画面下にヘイトゲージ)

### 8.2 敵の攻撃の種類(プロトタイプで追加。ユーザー指示 2026-11-21)

敵は攻撃のたびに、次の3種類から1つを選ぶ(ランダム。重みは たたきつけ0.4 / なぎはらい0.35 / とっしん0.25【仮】)。どれも予告(赤い表示と「！」)を出し、**予告の最後(「いま！」)に勇者がフリックすれば「いなす」で止められる**(ゆうしゃが狙われているとき。§5.2)。

| 攻撃 | 発動条件 | 予告 | 効果【仮】 | 対処 |
|---|---|---|---|---|
| たたきつけ | 狙う相手が接触範囲 | 0.7秒 | 単体。ゆうしゃ18(ふんばり8)/まほう15 | 離れる、ふんばる、いなす |
| なぎはらい | 狙う相手が接触範囲 | 0.95秒。足元に赤い円(半径は敵の半径+2.6) | 円内の**全員**。ゆうしゃ16(ふんばり7)/まほう13。吹き飛ばし1.4 | 円の外へ出る(後衛が巻き込まれやすい)、ふんばる、いなす |
| とっしん | 狙う相手が3〜9.5離れている | 0.9秒。足元に赤い帯(突進の道筋) | 一直線に秒速20で駆け抜け、当たった相手にダメージ。ゆうしゃ20(ふんばり9)/まほう18。吹き飛ばし1.2。終わると0.7秒つかれて動けない | 道筋から横へ避ける(ねらいは発動の0.45秒前に確定)、いなす。つかれた隙に攻撃する |

- 接触して押し合っているときは、たたきつけ/なぎはらいが中心で、とっしんは離れた(または後衛が狙われた)ときに出る。「押す・離れる・回り込む」の選択が増える狙い
- 調整(2026-11-21): 実機で「敵が遅く、ダメージが軽い」との指摘を受け、敵の移動速度を約1.5倍(さらに同日、もう一段上げて 軽い4.3/ふつう3.4/重い2.6。ゆうしゃは3.2→2026-11-21に5.2へ。ユーザー指示「ストレスがない感じがよい」。敵の最高速4.3より速く、指のドラッグ量も50→40pxで最大速度になるようにした)、攻撃間隔を1.8→1.4秒、ダメージを約1.5倍、押し合い反撃を28→36(ふんばり14)に上げた【仮】
- 調整(2026-11-21 夜): 「敵が弱い」との指摘を受け、敵のHPを約1.7倍(軽い110→190/ふつう150→260/重い220→370)、攻撃間隔を1.4→1.0秒、押し合い反撃後のよろけを1.6→1.2秒に変更【仮】
- 検証ポイント: とっしんの避けやすさ(後衛の自動回避が間に合うか)、なぎはらいで後衛が巻き込まれる頻度、攻撃が増えて「いなす」のフリックが忙しくなりすぎないか

### 8.3 止めの演出(ユーザー指示 2026-11-21)
- 敵のHPが0になる攻撃(止め)が入ると、敵は**画面の外へ飛んでいく**。回転しながら拡大し、残像と「キラーン！」を画面の端に出す(画面も揺れる)
- 飛ぶ向きは、止めを刺したフリックの向き(必ず少し上向きになるよう補正)。まほうつかいの魔法が止めのときは、ランダムな斜め上
- 最後の敵を倒したときは、飛んでいく演出が終わるのを待ってから(約1秒後)クリア表示を出す
- 勝利条件は変わらずHPで、押し出しは勝ちにならない(この演出は「倒した敵を飛ばす」だけで、場外判定とは無関係)

## 13. 実装メモ(スマホブラウザ)

### 3D風の作り方(候補)
| 方法 | 内容 | 向き不向き |
|---|---|---|
| Canvas 2D の疑似3D | 平面座標を透視変換(奥ほど小さく・上に)して拡縮した画像を並べる | 軽い。実装が簡単。背景・床はやや平面的 |
| WebGL(Three.js等) | 板ポリ+床+簡易ライト | 見た目の自由度が高い。読み込みサイズ・低スペック端末への配慮が必要 |

→ **最初は Canvas 2D の疑似3Dで作り、手触りを確認してから必要ならWebGL化**を推奨。ロジックは平面のまま、描画だけ差し替えられる構造にする。

### 共通
- 固定ステップ(1/60秒)で更新。実行フェーズの12秒はゲーム内タイマーで管理
- 数値は `config.json` に集約。シミュレーション(バランス確認)にも使う
- 当たり判定は円同士。押し込みは法線方向の位置補正(物理エンジン不要)
- スマホ必須対応: ダブルタップ拡大・ピンチ・スクロール・長押しメニューの抑止、非表示時の自動一時停止、音は最初のタッチ後に初期化。iPhoneは振動が使えないため見た目と音だけで成立させる

## 14. プロトタイプの進め方
