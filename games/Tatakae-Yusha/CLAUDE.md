# 戦え！ゆうしゃ（`games/Tatakae-Yusha/`）

ドラクエ10の戦闘「相撲システム」を発展させた、スマホ縦画面・ブラウザのソロゲーム（制作中。ポートフォリオにはまだ載せていない）。公開URL: `https://yoshida-std.github.io/website/games/Tatakae-Yusha/`
リポジトリ全体の作業ルールはルートの `CLAUDE.md` を参照。

プッシュ前の確認用 Artifact: `https://claude.ai/artifact/WwVmu9QYrayLdxw3Jn8GzQ`（変更のたびにこの URL を更新する。`index.html` と、`files` で `src/*.js` を同じパスで載せる。Artifact 側が外枠を付けるので、載せるときは `<!DOCTYPE>` `<html>` `<head>` `<body>` と charset・viewport の meta を外したコピーを使う）

設計書は `docs/new-sumo-system-design-v3.md`（現行DQ10の整理は `docs/dq10-sumo-system-spec.md`）。作業前に必ず読むこと。数値は【仮】で、調整前提。

## 構成（ビルドなし。ES モジュール）

- `prototype-2d.html` … 移行元のプロトタイプ（Canvas 2D、1ファイル）。**動作の基準として変更しない**
- `index.html` … 入口。DOM と CSS はプロトタイプと同じ。`src/main.js` を `type="module"` で読む
- `src/config.js` … CFG・視野（`CAM`。ひろい固定）・フリック感度・敵の種類。切りかえは `setFlickKey` / `setET`（import した変数は外から代入できないため）
- `src/screen.js` … キャンバス・画面の大きさ（CW/CH/DPR）・上のウィンドウの高さ。`onResize(f)` で ほかの描画も大きさを合わせる
- `src/logic.js` … 状態 `S`・入力 `inp`・`step()`。プロトタイプのコードをそのまま移したもの
- `src/records.js` … とうばつタイム（クリア時間）の記録（`localStorage`。ステージ × 敵のおもさごと）
- `img/stage-<id>.jpg` … ステージ選択のカードの絵。`node tools/stage-thumb.js [id]` で撮る（ゲームの画面から。UIをかくし、敵を勇者のほうへ向けて切り出す。`THREE_DIR` が要る）
- `src/stages.js` … **ステージのデータ**（`STAGES`）と、てきの種類（`ENEMY_KINDS`）。ステージ・敵を増やすのはここ（下の「ステージ選択」）
- `src/render2d.js` … Canvas 2D の描画（プロトタイプのまま）
- `src/main.js` … スマホのブラウザ動作の抑止・ループ・上のウィンドウのボタン・`window.__sumo`
- `src/render3d.js` … Three.js（WebGL）の描画。#gl（夜空・壁・床・しるし・キャラ）→ #c（HUD。移行元の 2D のコード）の順に重ねる
- `src/backdrop3d.js` … 背景の 3D 版。夜空（カメラについてくる半球＋シェーダーのグラデーション）・星（ちかちか）・星座（`CONSTEL`）、闘技場を囲む輪（半径 38、高さ 16、40区画）の壁（アーチ・柱・塔・あかりの窓。1つのジオメトリにまとめる）、たいまつ（加算合成のスプライトで炎のゆらぎ）。空の色の範囲は画面の上はしの角度 `atan(HZ/F)` に合わせる。遺跡の大きさ・高さは `WALL_R / WALL_H / BAYS`
- `src/three-chars.js` … キャラの 3D モデル（`{obj, update}` の形。glTF に差し替えやすくする）
- Three.js は importmap で `https://cdn.jsdelivr.net/npm/three@0.186.1/+esm`、追加部品（太い線）は `three/addons/` → `…/three@0.186.1/examples/jsm/` から読む（バージョン固定）
- 箱モデルの形・アニメは `render2d.js` の `heroParts` / `allyParts` / `enemyParts`（部品のリストを返す）を 2D と WebGL で共用する
- Three.js は部品を作るときに `Math.random` を使うので、`withOwnRandom` で別の乱数に切りかえてから作る（ゲームの乱数の並びを変えないため）
- アンチエイリアスは DPR 2 以上では切っている（スマホで重くなるため）
- `tools/sansmen.js` … キャラクターの**三面図**（正面・側面・背面。高さのガイド・寸法・色見本・くらべる勇者つき）を書きだす。`node tools/sansmen.js` でまほうつかい（`docs/mage-3view.png`）、`node tools/sansmen.js enemy` で敵のどすこいオーガ・ふつうの敵（`docs/enemy-3view.png`）、`node tools/sansmen.js hero` で勇者（`docs/hero-3view.png`。待機ポーズ・くらべる欄なし）。ゲームの実際のモデルをゲームと同じ大きさで真横から（`h3render` の `pitch=0`）描くので、モデルを変えて再実行すれば図も変わる。glTF などの本番モデルを作るときや、AI に絵を作りなおしてもらうときの資料にする
- `tools/bot.js` … ボット（headless）。使い方は JS 冒頭。`node tools/bot.js --compare prototype-2d.html,index.html` で移行元と勝敗・時間・毎フレームの状態を比べる
- この作業環境からは cdn.jsdelivr.net に接続できない。確認は `npm i three@0.186.1` をスクラッチに入れ、ボットは環境変数 `THREE_DIR` にその `node_modules/three` を指定する（Playwright で CDN への要求をそこへ回す）

## キャラクターデザインのスキル
- キャラを足す・デザインを変える・三面図を作る・画像生成AIにデザインを頼む、ときは、プロジェクトのスキル **`.claude/skills/tatakae-character-design/`**（`SKILL.md`）を使う。箱モデルの決まり（部品 80個以内・座標・回転・大きさの倍率）、今のキャラの数値と色、画像AIに渡す文面（三面図・色ちがい・ポーズ・デザイン変更）、チェックリストが入っている
- キャラの数値を変えたら、`.claude/skills/tatakae-character-design/references/characters.md` の表も合わせて直す

## 方針
- **開発は WebGL だけで進める**（ユーザー指示 2026-11-22）。**2D 表示（`?r=2d`）との比較・「毎フレームの状態が完全に一致」の確認は、もうしない**。確認はボット（`tools/bot.js`。1つの URL で勝敗・エラー・残った線や輪を見る）と、Playwright の画面確認でする。`render2d.js` は、HUD・箱モデルの部品・`h3render`（三面図）で使っているので残す。2D だけの描画（`?r=2d`）と `prototype-2d.html` は、直さなくてよい（壊れても気にしない）
- ゲームロジックは平面(x,z)の円。描画だけを差し替える。ロジック・数値(CFG)・入力処理は変更しない
- 返事・UI文言は日本語。ゲーム内の文字はひらがな中心、ドラクエ風の枠
- 作業は小さく分けて、段階ごとにコミットする。壊れたらすぐ戻せるようにする
- 新しい挙動を足したら、ボット(headless)のシミュレーションで確認できる形を残す

## パーティ設定（ユーザー指示 2026-11-22）
- **ゆうしゃは固定。のこり3枠を選べる**（まほうつかい・そうりょ・せんし・なし。**同じ職を何人入れてもよい**。例: せんし・せんし・そうりょ）。**1番目（ゆうしゃ）・2番目＝前衛、3・4番目＝後衛**（はじまりの位置。`logic.js` の `SLOT_POS`: 2番目 (-2.6,8.4)、3番目 (-1.8,5.0)、4番目 (1.8,5.0)。ゆうしゃは (0,7.8)）。**既定はゆうしゃのみ**（ひとりで戦う）
- 画面: タイトルの「パーティ」とステージ選択の「パーティ（タップでへんこう）」から開く（`#party`。わくごとに「なし／まほうつかい／そうりょ／せんし」を選ぶ。`main.js` の `buildParty`）。選んだらすぐ保存し、もどるとタイトル／ステージ選択にもどる。ステージ選択の上に今のパーティを出す
- **ブラウザに記憶**: `localStorage` の `ty_party`（`["warrior","warrior","priest"]` のように3わくぶん。あいている わくは `null`）。起動時に読み込む
- 仕組み: 味方は**職ごとの決め打ち（`S.ally`/`S.priest`/`S.warrior`）をやめ、リスト `S.allies`**（`{id:'m0'〜'm2', kind:'mage'|'priest'|'warrior', slot:2〜4, x,z,r,hp,maxHp,mp,maxMp,flash,…}`。`init` が `partyKinds` から `makeAlly` で作る）。ねらい・ヘイトの名前は `'hero'` と `'m0'〜'm2'`（`unitOf(id)`）。ステータスは職ごとに `CFG.ally`（まほうつかい）/ `CFG.priest` / `CFG.warrior`（`KINDS[kind].cfg`）。`setParty(arr)` / `getParty()` / `partyKey()`（きろくの なまえ）。ボット・撮影ツールは `window.__sumo.setParty([...])` で指定する
- 動き: まほうつかい＝`stepMage`、そうりょ＝`stepPriest`、せんし＝`stepWarrior`（どれも1人ぶんの関数。人数ぶん呼ぶ）。飛んでいく炎は `stepSpells`（1回）、いやしの じんは `stepZones`（1回）。**いやしの じんは そうりょ1人につき同時に1つ**（`z.by`）。敵のとっしんが味方に当たったかは `e.hitIds`（人ごと）
- **とうばつタイムの記録は「ステージ × 敵のおもさ × パーティ」ごと**（`records.js`。パーティが違うと別の記録。ゆうしゃのみ＝`solo`、れいに `mage_priest_warrior`。あいている わくは `-`）
- 描画: 3わくぶんのモデルを使いまわす（`three-chars.js` の `allies[]`。職が変わっても `BoxModel` は同じ）。下のウィンドウは「わく番号どおり」に並べる（あいている わくは空の枠）
- ボット: `--party mage,priest,warrior`（既定）。`--party none` でゆうしゃのみ。同じ職を重ねてもよい。結果に `party`（職:HP）・`zonesMade`・`healed`・`shoves`
- ボットの結果（スマート・ふつうの敵・各1戦）: ゆうしゃのみ＝勝ち（32.4秒・ゆうしゃ HP 62）／せんし・せんし・そうりょ＝勝ち（23.5秒・HP 89）／まほうつかい・そうりょ・せんし＝勝ち（22.4秒・HP 100）。パーティが増えるほど早く・楽に勝つ。ゆうしゃのみは、ボット（「いま！」のいなしがうまい）だと勝てるが、人が遊ぶとかなりきびしい見込み（未確認）

## せんし（近接の前衛。ユーザー指示 2026-11-22）
- パーティに入れられる職のひとつ（上の「パーティ設定」）。**近距離で敵に斧で切りかかり、近づく敵を押す**。デザインはユーザーが渡した「せんし（おっさんのせんし）」の三面図（ひげ、はちがね・はなあて・とさかのかぶと、あかいよろいしたに茶いろのむねあて、茶いろのかたあて、ベルト＋金のバックル、あかいまえだれ・すそよろい、すねあて・ブーツ、背中のまるいたて、りょうばの大斧）。形は `render2d.js` の `warriorParts`（約 62 部品）、**大きさは勇者と同じ（`WARRIOR_SCALE = 1.0`。モデルの高さ 2.18）**、三面図は `docs/warrior-3view.png`（`node tools/sansmen.js warrior`）
- 数値は `CFG.warrior`（HP 130・速さ 3.6・**よろい 0.7＝敵から受けるダメージが 7 割**・当たり判定 r 0.62・重さ 130。MP は見た目だけ【仮】）
  - **きりかかり**: いちばん近い敵（まほうつかい・そうりょをねらっている敵は 5 ぶん優先して近いことにする）へ歩いて近づき、とどく距離（おたがいの半径＋1.6）に入ったら斧をふる。ふりかぶり 0.32 秒（その場でふんばる）→ダメージ 14 → 休み 1.3 秒。ダメージを与えるとヘイトがたまる（勇者と同じ倍率 `perDmg`）
  - **おす**: 近く（半径＋1.7）に来た敵を、うしろへ**おしやり**（`kx/kz` に 46）、**こうげきの予告を止めて** `atkCd` を 0.8 秒以上にし、**0.6 秒よろけさせる**（よろけた敵には勇者のスキダメージ 2.2 倍が入る）。休み 5 秒。「おす！」の文字と輪。敵のヘイトも少しもらう（12）
  - 動きは `logic.js` の `stepWarrior`。見た目の進みは `warriorSwingK(w)`（0〜0.4＝ふりかぶり／0.4〜0.55＝ふりぬき／0.55〜1＝もどり）と `warriorShoveK(w)`。斧のふりは「うでの角度 θ」と「斧のあたまの向き a」で組み、てくびでの回転は a−θ（`warriorParts`）
- 敵は**せんしもねらい、攻撃も当たる**（ヘイト `hate.warrior`、`unitOf('warrior')`）。**ふみこみ（lunge）はせんしにも勇者と同じようにかかる**（まほうつかい・そうりょにはかからない）。倒れたらその場に倒れたままで、負けにならない
- 下のウィンドウは4枠目（「せんし」。ターン＝つぎのふりまでのチャージ／ふりかぶりの進み。注に「おので きる」「おす」）
- ボットの結果に `shoves`（おすを使った数）を足した

## そうりょ（ヒーラー。ユーザー指示 2026-11-22）
- パーティに入れられる職のひとつ。**こうげきはしない**。デザインはユーザーが渡した「そうりょの女の子」の三面図（しろい大きなぼうし＝金のふちの十字・水いろのおび、ながいこげちゃの髪、しろいローブ＋水いろのまえかけ・金の十字、水いろのスカート・しろいすそ、しろいくつした・かわのくつ、金の十字の杖＋クリスタル）。形は `render2d.js` の `priestParts`（約 72 部品）、大きさは勇者に合わせて `PRIEST_SCALE = 0.76`、三面図は `docs/priest-3view.png`（`node tools/sansmen.js priest`）
- 数値は `CFG.priest`（HP 80・MP 70・毎秒 1 回復・速さ 2.0。**きびしめ**の回復）【仮】
  - **ヒール**: 詠唱 0.9 秒・MP 10・休み 5 秒。そうりょの近く（半径 4.5）の味方（ゆうしゃ・まほうつかい・自分）を**一度に 20** 回復。かけている HP が 12 以上の味方がいるとき使う
  - **いやしの じん**: 詠唱 1.2 秒・MP 20・休み 8 秒。いちばんきずついた味方の足もと（敵から少しはなれた側）に、半径 3 の**じん**（`S.zones`）を出す。**のっている味方は 0.5 秒ごとに 2（毎秒 4）回復**、**8 秒で消える**（消える直前は点滅）。**同時に 1つだけ**。かけている HP が 24 以上の味方がいて、じんがないときに使う（ヒールより先）
  - MP が足りないと使わない（「MPが たりない！」）。詠唱中は動けない。敵の攻撃が自分に来る予告のあいだは詠唱を始めず、逃げる（まほうつかいと同じ。`casterMove`）
- **敵はそうりょもねらい、攻撃も当たる**（まほうつかいと同じ。ヘイトは `hate.m0〜m2`、ねらい `e.target==='m0'` など、`unitOf(who)` で本人を取る）。倒れたら（HP 0）その場に倒れたままで、回復もしなくなる。倒れても負けにならない。**回復はヘイトを集める**（回復した HP × `hate.perHeal` 0.6。じんの回復は半分）
- AI: まほうつかいと同じ移動（敵から離れる）に、**ゆうしゃから 4.5 以上離れないよう近づく**力（`stay` / `stayW`）。きずついているときは、いやしのじんの中へ入りたがる（まほうつかい・そうりょ）
- 見た目: 詠唱中は杖のクリスタルがみどりに光る。ヒールは対象の足もとに みどりの輪と「+20」。じんはゆかに みどりの円（まわる十字・のぼる光の粒）。下のウィンドウは3人目（「そうりょ」。ターン＝詠唱の進み／休みのチャージ。注に「ヒール」「いやしの じん」）
- ボット（`tools/bot.js`）の結果に `priestHp` `zonesMade`（じんを作った数）`healed`（味方の HP がふえた合計）を足した
- 新しい職を足すときは、`KINDS`（`logic.js`）に足し、`makeAlly` と動き（`step` のなかの味方のループ）、`CFG`、見た目（`*Parts`・`three-chars.js`・`charModel`・下のウィンドウの `hudMember`）、パーティ画面の説明（`index.html` の `.legend`）を足す

## まほうつかいのデザイン（ユーザー指定 2026-11-22）
- まほうつかいは**女の子**（ユーザーが渡した「まほうつかいの女の子 戦闘ポーズ集」のデザイン）。むらさきのとんがりぼうし（金のおびと右前のリボン、先に金のかざり）、オレンジの髪（まえがみ・ツインテールの三つ編み）、大きな頭（目・ほほ・まゆ・くち）、金のふちの上着と金のすじ・きいろいリボン、プリーツのスカートとしろい裾、短い足（くつした・かわのくつに金具）、水色のクリスタルの杖（金のわ・はめこみ）。ちびキャラの体型（頭が大きく足が短い）
- 形は `render2d.js` の `allyParts`（箱の部品 約 68 個。`BoxModel(80)` の範囲）。詠唱中のクリスタルの色（オレンジ）と大きさ、倒れるときの動き、歩きのアニメは前のまま
- **大きさは勇者に合わせた**（ユーザー指示 2026-11-22）。モデルそのものの背たけは 2.85（勇者 2.17）なので、見た目だけ `MAGE_SCALE = 0.76` 倍（`render2d.js`。2D の `drawAlly` と WebGL の `ally.set` が使う）。これで背たけ・頭の大きさが勇者とそろう。**当たり判定（`CFG.ally.r`）は変えていない**。炎の出る高さ・ダメージ数字・文字の高さも 0.76 倍に合わせた。三面図は同じ縮尺で、右端に勇者を並べて比べられる
- **三面図**は `docs/mage-3view.png`（`tools/sansmen.js` で作る）。モデルを変えたら再実行する
- 元の絵のポーズ（杖でスイング・詠唱チャージ・魔法発射・バリア）は まだ作っていない（今は待機・詠唱・倒れるだけ）

## 負けるのは勇者だけ（ユーザー指示 2026-11-22）
- **勇者以外（まほうつかい）が倒れても負けにならない**。負けるのは勇者のHPが 0 になったときだけ（`step` の最後）
- 倒れたまほうつかいは、**その場でうしろへ倒れ（よこむきになって）、そのまま**。詠唱をやめる（すでに飛んでいる炎は当たる）。敵は狙わなくなり（ヘイト 0・狙いをはずす）、攻撃も当たらない（`hitAlly` ほか）。押し合いでもじゃまにならない。足もとの紫の輪は出さない。下のウィンドウは暗くなる
- 見た目は `heroParts` の倒れ方と同じ考え（`allyParts` の `down`。`allyDown(a)` が 0〜1。`downT` は `stepFx` で進める）
- 「まほうつかいが たおれた…」の結果表示は使わなくなった（`endGame('ally')` は呼ばない）

## ステージ選択（ユーザー指示 2026-11-22）
- 「どすこいオーガ4匹」は**1つのステージ**（`id: 'ogre4'`）。今後、ステージ・敵キャラを増やしていく。パーティ設定は下の「パーティ設定」
- 流れ: **タイトル**（`#title`。ボタンは「はじめる」「せつめい」の2つ）→「はじめる」で **ステージ選択**、「せつめい」で説明の画面（`#intro`。「もどる」でタイトルへ）。ステージ選択にも「タイトルへ」がある。ステージ選択（`#stages`。`STAGES` からカードを作る。`main.js` の `buildStageList`）→ えらぶと `init(id)` でそのステージがはじまる。上のウィンドウの「ステージえらび」でステージ選択にもどる（ゲームは止まる）。最後に遊んだステージは `localStorage` の `ty_stage` に覚えて、一覧で「まえに あそんだ」と出す

## 敵の踏みこみ（ユーザー提案 2026-11-22）
- 理由: 以前は、敵の近い攻撃（たたきつけ・なぎはらい）は予告中に敵が動かず、勇者のほうが速い（秒速 5.2 対 2.6〜4.3）ため、**予告を見て後ろへさがるだけで全部かわせた**（`tools/` の試験で 100%）。とっしんは、まっすぐでも横でもかわせる（今のまま）
- 仕組み: 敵の **HP が半分以上（`CFG.lunge.hpRatio`）あるときだけ**、近い攻撃の**当たる瞬間**に、ねらった相手のほうへ踏みこむ（`lungeLanding`。たたきつけ 1.5・なぎはらい 1.5）。踏みこんだ先で当たりを取る。相手の体にはめりこまない。HP が半分より少ない敵は踏みこまない（余裕がないので）
- 見せ方: 予告中、足もとの赤い円を**踏みこんだ先**に出す（`drawGroundMarks`）。たたきつけにも円が出る。いなす範囲も踏みこみのぶん広がる
- 結果（敵が勇者をねらっているとき、`dodge` 試験）: すぐ（反応 0 秒）にさがれば今までどおりかわせる。反応が 0.25 秒おくれると、たたきつけは重い敵に当たり、なぎはらいは全部当たる。0.5 秒おくれだと両方とも全部当たる。横へ逃げるのは近い攻撃には効かない（今までと同じ）。→ ふんばる・いなす（`！` に合わせたフリック）を使う意味が出る
- まほうつかいが狙われたときは踏みこまない（`lunge.ally: 0`。まほうつかいは敵より遅いので、踏みこむと必ず当たってしまう）。代わりに詠唱中は動けない（下記）
- 試験の道具は作業用の場所にあるだけ（リポジトリには入れていない）。やり方: 敵を1体にして勇者をまんなかに置き、攻撃の種類を決めて、予告から delay 秒あとにさがる/横へ動く、を 12 回ずつ

## 勇者のポーズ（ユーザー指示 2026-11-21）
- **剣ふり**（ユーザー指示 2026-11-21「右斜上から左下に振ったり、大きく左から右に振ったり」）: フリックの向きに合わせて、肩を中心に剣を大きく振る。ためる（反対がわへ引く）→ふりぬく→のこし→もとへ、の約 0.34 秒（見た目だけの `h.swingV`。判定の `swingT=0.2` は変えていない）。振る面は「正面」と「フリックの向き」に垂直な軸（`Rz(φ)·Rx(θ)·Rz(-φ)`）で、向きの正負は剣先の画面での動きから決める。横ぶりは約 92°、たてぶりは約 72°。体もひねり・のけぞり／かたむく。白い軌跡は大きな弧にして、ふりぬく間だけ出す
- 剣をふる間、勇者は**フリックの向きを向かず、敵のほう（後ろ向き）を向く**（画面で振りの向きがそのまま見えるように変更。以前は振った向きを 0.35 秒向いていた）
- 「おす」: 両手を前にのばして押す。体を前にかたむけ、足は前後に開く。手は少し中央に寄せ、押す力のぶんだけ小さくふるえる。剣は右手で立てたまま
- 「ふんばる」（止まっているときも）: 両足を開いて少し腰を落とし、両腕も開きぎみに。呼吸のように体・腕がゆっくり上下にゆれる（約 0.5 秒周期の `sin(t*3)`）
- ポーズの強さ `h.pushK / h.firmK`（0〜1）は `logic.js` の `step` でなめらかに変える（見た目だけに使う）。形は `render2d.js` の `heroParts`（WebGL も同じ部品リストを使う）。剣をふる間は、ひらいた右うでをもどす
- 歩き（`normal`）は今までどおり

## 土俵と地面（ユーザー指示 2026-11-21）
- 土俵の大きさを2倍にした（`CFG.arena.R` 11→22。中心 `cx,cz` は同じ）。**移行元（`prototype-2d.html`、R=11）とは、ロジックの数値がこの1点だけ ちがう**。ボットで移行元と比べるときは、土俵の大きさのぶん結果が変わる。描画だけの確認は `index.html?r=2d` と `index.html` の比較（毎フレーム完全一致）で行う
- 地面は添付の参考画像（大きな石板の石畳、すりへり、金の輪ときざみの象がん、土俵の外に のぼり階段）に合わせた。`render3d.js` の床のシェーダー（石板の目地・ふちの面とり・石ごとの色むら・よごれ・土俵のあかるさ・金の輪・きざみ・放射線）と、土俵の外の階段（2段のメッシュ）、キャラの かげ。土俵のふちの金線 `r=R` が場外の目じるし
- 壁の輪は土俵に合わせて広げた（`backdrop3d.js` の `WALL_R=60 / WALL_H=22 / BAYS=64`）

## ロジックと描画の境目（注意）
- 敵の見た目は当たり判定 `e.r` の 1.4 倍（`render2d.js` の `ENEMY_LOOK`。ユーザー指示「2まわり大きく」）。ロジックの大きさは変えていない。タップ・フリックの判定範囲・頭上の表示・止めの演出も見た目に合わせる。このため移行元（`prototype-2d.html`）とはフリックの当たり方が少しちがう（ボットの完全一致の比較は `index.html?r=2d` と `index.html` で行う）
- `render` が敵の画面上の位置と大きさ `e.sx / sy / shw / shh / sc` を書き、入力（`enemyAt`・`tapLock`）と止めの演出（`launchEnemy`）が読む。描画を変えても同じ値を書くこと
- 止めの演出 `S.fly` は画面の座標（px/秒）で動く（`stepFx` が `CW/CH` を使う）
- `faceTo()`（描画の中）が、まほうつかい・敵の向き `yaw3` と歩きのアニメ `mv3 / ph3` を更新する。勇者の `yaw3` は `step` で決まり、カメラから見た向き
- カメラは「視線は水平・画像の中心を地平線 `HZ` へずらした」投影（`proj()`）。下に傾けたカメラではない

## スマホ必須対応
- viewport: user-scalable=no、viewport-fit=cover
- touch-action: none(キャンバス)、overscroll-behavior: none
- touchstart で preventDefault(ボタン・メニュー以外)。ダブルタップ拡大・ピンチ・長押しメニュー・スクロールを抑止
- 入力は pointer イベント。音は最初のタッチ後に初期化
- 表示が隠れたら自動で一時停止

## 重要な操作仕様(変えないこと)
- ロック式の相対操作: 上=おす、左右=まわりこみ、下=さがる、止める=ふんばる
- 速いフリック=剣を振る(向き自由)。敵に重ねた操作は移動にならない
- 敵の「いま！」(予告の最後0.4秒)のフリック=いなす。振った直後0.5秒はいなせない
- 「おす」0.3秒以上の間は剣を振れない。きりょくゲージ(いきぎれ)あり
- 敵を押し出しても勝てない。勝敗はHP制
- 勇者の足もとは画面の上から50%。**視野は「ひろい」に決定**（`CFG` の `CAM`。切りかえの3段階とボタンはやめた。ユーザー指示 2026-11-21）
- **土俵の外に出てもダメージなし**。ふちで止まるだけ（`clampArena`。ばがいダメージ・硬直・復帰はやめた）
- **敵のターゲット表示はなし**（頭上の「A▶まほう」・ねらい線・「ねらわれた！」などの文字）。ターゲットの中身（ヘイトでの切りかえ）は今のまま動いている
- 「てきが せまってくる」の表示はなし
- 勇者の頭上の行動の吹き出し（「ふんばる」「おす」など）はなし。右上の「ロック: てきA」もなし（ロックの仕組みは動いている。きりょくゲージと「いきぎれ」は残してある）
- 上のウィンドウは右上のボタンで隠せる

## 描画の現状
- 勇者・まほうつかい・敵: ローポリの箱モデル(drawHero / drawAlly / drawEnemy)。向きは連続角度(yaw)
- 床・背景: Canvas 2D の手続き描画(夜の遺跡の闘技場)
- ダメージ数字・名前・HPバー: Canvas上に重ねて描く

## WebGL化（進め方）
0. ロジックを ES モジュールに分ける（描画は Canvas 2D のまま）… 済み
1. 床・カメラ（キャラは仮の円柱）… 済み（`src/render3d.js`・`src/three-chars.js`。`?r=2d` で移行元の描画、`?fps=1` でフレームレート表示）
2. 勇者 … 済み（`three-chars.js` の `BoxModel`。移行元の `heroParts` の部品リストから、毎フレーム 面のメッシュ1つと ふちの太い線（`LineSegments2`、太さ 0.032 は世界の長さ）1つを作る。キャラ1人あたり描画2回）
3. まほうつかい・敵・止めの演出 … 済み（`allyParts` / `enemyParts` から同じ `BoxModel` で描く。ふちの線の太さはモデルの大きさに合わせる。止めの演出は移行元と同じく画面の座標（px）で動くので、画面の座標の平行投影カメラ（`ortho`）で描き、移行元と同じ 0.38 のかたむきを付ける。浮かぶ文字は WebGL の上の HUD に描くので、飛んでいく敵より手前に出る（移行元とのちがい）)
4. 背景・仕上げ … 背景は済み（実測は下の「実測」）。最適化は実機の数字を見てから
5. ボットで移行前と比べる

## 実測（段階4の時点。この作業環境は GPU なしのソフトウェア描画なので、フレームレートは目安にならない）
