# 戦え！ゆうしゃ（`games/Tatakae-Yusha/`）

ドラクエ10の戦闘「相撲システム」を発展させた、スマホ縦画面・ブラウザのソロゲーム（制作中。ポートフォリオにはまだ載せていない）。公開URL: `https://yoshida-std.github.io/website/games/Tatakae-Yusha/`
リポジトリ全体の作業ルールはルートの `CLAUDE.md` を参照。

プッシュ前の確認用 Artifact: `https://claude.ai/artifact/WwVmu9QYrayLdxw3Jn8GzQ`（変更のたびにこの URL を更新する。`index.html` と、`files` で `src/*.js` を同じパスで載せる。Artifact 側が外枠を付けるので、載せるときは `<!DOCTYPE>` `<html>` `<head>` `<body>` と charset・viewport の meta を外したコピーを使う）

設計書は `docs/new-sumo-system-design-v3.md`（現行DQ10の整理は `docs/dq10-sumo-system-spec.md`）。作業前に必ず読むこと。数値は【仮】で、調整前提。

## 構成（ビルドなし。ES モジュール）

- `prototype-2d.html` … 移行元のプロトタイプ（Canvas 2D、1ファイル）。**動作の基準として変更しない**
- `index.html` … 入口。DOM と CSS はプロトタイプと同じ。`src/main.js` を `type="module"` で読む
- `src/config.js` … CFG・視野（`CAM`。ひろい固定）・フリック感度・敵の種類。切りかえは `setFlickKey` / `setET`（import した変数は外から代入できないため）
- `src/screen.js` … キャンバス・画面の大きさ（CW/CH/DPR）・上のウィンドウの高さ。`onResize(f)` で ほかの描画も大きさを合わせる
- `src/logic.js` … 状態 `S`・入力 `inp`・`step()`。プロトタイプのコードをそのまま移したもの
- `src/render2d.js` … Canvas 2D の描画（プロトタイプのまま）
- `src/main.js` … スマホのブラウザ動作の抑止・ループ・上のウィンドウのボタン・`window.__sumo`
- `src/render3d.js` … Three.js（WebGL）の描画。#gl（夜空・壁・床・しるし・キャラ）→ #c（HUD。移行元の 2D のコード）の順に重ねる
- `src/backdrop3d.js` … 背景の 3D 版。夜空（カメラについてくる半球＋シェーダーのグラデーション）・星（ちかちか）・星座（`CONSTEL`）、闘技場を囲む輪（半径 38、高さ 16、40区画）の壁（アーチ・柱・塔・あかりの窓。1つのジオメトリにまとめる）、たいまつ（加算合成のスプライトで炎のゆらぎ）。空の色の範囲は画面の上はしの角度 `atan(HZ/F)` に合わせる。遺跡の大きさ・高さは `WALL_R / WALL_H / BAYS`
- `src/three-chars.js` … キャラの 3D モデル（`{obj, update}` の形。glTF に差し替えやすくする）
- Three.js は importmap で `https://cdn.jsdelivr.net/npm/three@0.186.1/+esm`、追加部品（太い線）は `three/addons/` → `…/three@0.186.1/examples/jsm/` から読む（バージョン固定）
- 箱モデルの形・アニメは `render2d.js` の `heroParts` / `allyParts` / `enemyParts`（部品のリストを返す）を 2D と WebGL で共用する
- Three.js は部品を作るときに `Math.random` を使うので、`withOwnRandom` で別の乱数に切りかえてから作る（ゲームの乱数の並びを変えないため）
- アンチエイリアスは DPR 2 以上では切っている（スマホで重くなるため）
- `tools/bot.js` … ボット（headless）。使い方は JS 冒頭。`node tools/bot.js --compare prototype-2d.html,index.html` で移行元と勝敗・時間・毎フレームの状態を比べる
- この作業環境からは cdn.jsdelivr.net に接続できない。確認は `npm i three@0.186.1` をスクラッチに入れ、ボットは環境変数 `THREE_DIR` にその `node_modules/three` を指定する（Playwright で CDN への要求をそこへ回す）

## 方針
- ゲームロジックは平面(x,z)の円。描画だけを差し替える。ロジック・数値(CFG)・入力処理は変更しない
- 返事・UI文言は日本語。ゲーム内の文字はひらがな中心、ドラクエ風の枠
- 作業は小さく分けて、段階ごとにコミットする。壊れたらすぐ戻せるようにする
- 新しい挙動を足したら、ボット(headless)のシミュレーションで確認できる形を残す

## 勝ったとき（ユーザー指示 2026-11-22）
- 終わったとき（`endGame`）に、のこっている攻撃のビーム `S.beams` と剣の軌跡 `swingV` を消す。ゲームの時間がとまるので、消さないと黄色い線（勇者のビーム）が演出の間ずっと残る（最後の一撃のビームが残っていた）。ボット（`tools/bot.js`）の結果に `beamsAtEnd` を足した
- 勇者の背中に**鞘**がある（右かたから左こしへ ななめ。常に見える。剣を抜いた状態では空）。体のかたむき・ひねり（`lean`/`twist`）は、足より上（胴体・あたま・うで・剣）にかかる（`legCount` を足のすぐあとに置いた。以前は うで・剣 にしか かかっていなかった）
- 勝ち方で3パターン。**勝った瞬間の勇者のHPの割合**で決める（`CFG.victory`: 70%以上=余裕 `easy` / 35%未満=辛勝 `close` / その間=普通 `normal`。`endGame('win')` が `S.victory.grade` に入れる）
  - 余裕: 胸の前で左手を上下にして、服のほこりを**3回**払う（ほこりの粒が ぱらぱら落ちる `S.dust`・「パッパッ」）。そのあと剣をかかげ→肩ごしに背中へまわし→**背中の鞘に収める**（「チャキン！」）。収めたあとは柄だけが右肩の後ろに見える。約 4 秒かかる（`heroParts` の `vt` の 0.4〜2.05 が払い、2.2〜3.45 が納刀、3.45〜3.95 で手がもどる）
  - 普通: ガッツポーズ。右手の剣を高くかかげ（手首で剣だけまっすぐ立てる）、左こぶしを突きあげ、はねる。「やったー！」。ジャンプは、着地とつぎの踏み切りの前で**体が沈み**（`crouch`。足を開き、体を前にかたむけ、左こぶしをさげる）
  - 辛勝: あぐらで地面にすわりこみ（体を床まで下げ、両足を前に倒して ×に組む）、左手でグッド（おやゆび）。剣は体の横に寝かせる。**息づかいを大きく**（約 1.9 秒周期。体の上下 ±0.05・前後のゆれ ±0.09・グッドの腕のゆれ）。「ぜぇ…ぜぇ…」を約 1.9 秒おきに出す
- 流れ: 最後の敵が飛んでいったあと、カメラが約1.3秒で勇者の正面へまわりこみ（`victoryCam`。距離 8.2→4.4、高さ 5.2→2.2）、勇者もカメラのほうを向いて（`h.yaw3`）ポーズ（約0.5秒でふんばりの姿勢から変わる）。結果（「てきを ぜんぶ たおした！」・勝ち方の一言・クリアタイム）は画面の上に出し（暗幕はうすく）、出す時間は余裕＝約 5.2 秒（納刀が終わってから）・ほか＝約 3.0 秒、その 0.4 秒あとから「タップで もういちど」（`overShowT` / `overReadyT`）
- 仕組み: `step` が `S.over` の間 `stepVictory(dt)` を動かす。姿は `heroParts` の `VIC`（`S.victory` の勝ち方と時間から腕・足・体を作る）

## ゆうしゃが負けたとき（ユーザー指示 2026-11-21）
- HP が 0 になると、勇者が後ろへ倒れ（横向きにまわりながら）、2体の敵が勇者の左右に走ってきて囲み、腕をふりあげてはたたきつけ（ボコボコ）続ける。たたくたびに体がはね、画面がゆれ、「ドガッ！」「ボコッ！」などの文字と短い振動が出る。カメラは約2秒かけて高く上がり（高さ 5.2→11、勇者までの距離 8.2→6.2）、勇者を見下ろしながら少しまわりこむ（`defeatCam`。ユーザー指示「やられた時カメラの位置を上げて見下ろす感じ」）
- 約 2.6 秒たってから、暗くして「ゆうしゃは たおれた…」を出し（演出と重ならないよう、文字の位置は画面の上のほう。`render2d.js` の `TY`。勇者が倒れたときだけ。ほかは今までの位置）、約 3.0 秒から「タップで もういちど」（`overShowT` / `overReadyT`）。まほうつかいが倒れたときは今までどおり（すぐ表示）
- 仕組み: `endGame('hero')` が `S.defeat` と `h.dead` を立てる。`step` が `S.over` の間、`stepDefeat(dt)` を動かす（敵の移動・たたく動き `beatPhase`・カメラ）。倒れる姿は `heroParts`（痛恨のふっとびと同じ仕組み。痛恨で死んだときは飛んだ先でそのまま倒れたまま）
- 白くひかる点滅は、ゲームの時間が止まっていても動くよう `blinkNow()`（`S.t + S.overT + intro.t`）を使う

## 痛恨の一撃（ユーザー指示 2026-11-21）
- 「痛恨攻撃」＝敵の**押し合い反撃**（ねばりゲージ満タンで出る「はんげき」。ダメージ36）。これが**ふんばらずに当たる**と、勇者は後ろへ約7ふっとび（`CFG.counter.crit.dist`）、**2秒間うごけない**（`crit.stun`。移動・剣ふり・いなす不可。`h.stun`）。ふんばって受けたとき（`dmgFirm` 14）は、これまでどおり小ダメージで飛ばない
- ふっとびの動き: `h.kx/kz` の速度が `exp(-k dt)` で減る（`logic.js`）。見た目は `heroParts` の最後（後ろむきに1回転して飛び、あおむけに倒れ、最後の 0.5 秒で起き上がる）。ふっとび中・動けない間は、勇者は向きを変えず、歩きのアニメも止める
- ほかの攻撃（たたきつけ・なぎはらい・とっしん）は変えていない。ほかの攻撃にも痛恨を付けたいときは、当たったところで `h.kx/kz` と `h.stun/stunMax` を同じように設定する

## ゲームスタートの演出（ユーザー指示 2026-11-21）
- 「はじめる」「やりなおし」（`init()`）のたびに、約 4.3 秒の演出が入る（`logic.js` の `INTRO`・`S.intro`）。演出の間はゲームを止める（`step` が `stepIntro` だけ動かす。`S.t` は進まない）。**タップで飛ばせる**（はじまって 0.4 秒すぎてから。`skipIntro()`）
- 流れ: カメラが敵Aの足もとを大きく写す（低い位置）→ 敵Aが上から降りて地面に着地（「ドシン！」・画面ゆれ・ひろがる輪・振動）→ カメラが敵Bへ移る → 敵Bも着地 → カメラがゲームの位置まで引く（ゲームの位置は `CAM`＝ひろいの位置で、勇者の足もと50%）
- カメラはキーフレーム3つ（Aのクローズアップ・Bのクローズアップ・ゲームの位置）の間を `introState(S)` が補間する（位置・向き・高さ・画角・注目点）。`render2d.js` の `setupView` が演出中は `introState` から `V` を作る。注目点の足もとが画面のたて `yf` に来るように地平線 `HZ` を決める（ゲームの位置では `HERO_Y`）
- 敵の `air`（高さ）で落下を表す。空中の間は、両手をふりあげた姿勢・しるし（当たり円・予告）・頭上の表示を出さない。着地点には、近づくほど大きく濃くなる影が出る
- ボットは演出を飛ばす（`window.__sumo.skipIntro()`）

## 勇者のポーズ（ユーザー指示 2026-11-21）
- **剣ふり**（ユーザー指示 2026-11-21「右斜上から左下に振ったり、大きく左から右に振ったり」）: フリックの向きに合わせて、肩を中心に剣を大きく振る。ためる（反対がわへ引く）→ふりぬく→のこし→もとへ、の約 0.34 秒（見た目だけの `h.swingV`。判定の `swingT=0.2` は変えていない）。振る面は「正面」と「フリックの向き」に垂直な軸（`Rz(φ)·Rx(θ)·Rz(-φ)`）で、向きの正負は剣先の画面での動きから決める。横ぶりは約 92°、たてぶりは約 72°。体もひねり・のけぞり／かたむく。白い軌跡は大きな弧にして、ふりぬく間だけ出す
- 剣をふる間、勇者は**フリックの向きを向かず、敵のほう（後ろ向き）を向く**（画面で振りの向きがそのまま見えるように変更。以前は振った向きを 0.35 秒向いていた）
- 「おす」: 両手を前にのばして押す。体を前にかたむけ、足は前後に開く。手は少し中央に寄せ、押す力のぶんだけ小さくふるえる。剣は右手で立てたまま
- 「ふんばる」（止まっているときも）: 両足を開いて少し腰を落とし、両腕も開きぎみに。呼吸のように体・腕がゆっくり上下にゆれる（約 0.5 秒周期の `sin(t*3)`）
- ポーズの強さ `h.pushK / h.firmK`（0〜1）は `logic.js` の `step` でなめらかに変える（見た目だけに使う）。形は `render2d.js` の `heroParts`（WebGL も同じ部品リストを使う）。剣をふる間は、ひらいた右うでをもどす
- 歩き（`normal`）は今までどおり

## 土俵と地面（ユーザー指示 2026-11-21）
- 土俵の大きさを2倍にした（`CFG.arena.R` 11→22。中心 `cx,cz` は同じ）。**移行元（`prototype-2d.html`、R=11）とは、ロジックの数値がこの1点だけ ちがう**。ボットで移行元と比べるときは、土俵の大きさのぶん結果が変わる。描画だけの確認は `index.html?r=2d` と `index.html` の比較（毎フレーム完全一致）で行う
- 地面は添付の参考画像（大きな石板の石畳、すりへり、金の輪ときざみの象がん、土俵の外に のぼり階段）に合わせた。`render3d.js` の床のシェーダー（石板の目地・ふちの面とり・石ごとの色むら・よごれ・土俵のあかるさ・金の輪・きざみ・放射線）と、土俵の外の階段（2段のメッシュ）、キャラの かげ。土俵のふちの金線 `r=R` が場外の目じるし
- 壁の輪は土俵に合わせて広げた（`backdrop3d.js` の `WALL_R=60 / WALL_H=22 / BAYS=64`）

## ロジックと描画の境目（注意）
- 敵の見た目は当たり判定 `e.r` の 1.4 倍（`render2d.js` の `ENEMY_LOOK`。ユーザー指示「2まわり大きく」）。ロジックの大きさは変えていない。タップ・フリックの判定範囲・頭上の表示・止めの演出も見た目に合わせる。このため移行元（`prototype-2d.html`）とはフリックの当たり方が少しちがう（ボットの完全一致の比較は `index.html?r=2d` と `index.html` で行う）
- `render` が敵の画面上の位置と大きさ `e.sx / sy / shw / shh / sc` を書き、入力（`enemyAt`・`tapLock`）と止めの演出（`launchEnemy`）が読む。描画を変えても同じ値を書くこと
- 止めの演出 `S.fly` は画面の座標（px/秒）で動く（`stepFx` が `CW/CH` を使う）
- `faceTo()`（描画の中）が、まほうつかい・敵の向き `yaw3` と歩きのアニメ `mv3 / ph3` を更新する。勇者の `yaw3` は `step` で決まり、カメラから見た向き
- カメラは「視線は水平・画像の中心を地平線 `HZ` へずらした」投影（`proj()`）。下に傾けたカメラではない

## スマホ必須対応
- viewport: user-scalable=no、viewport-fit=cover
- touch-action: none(キャンバス)、overscroll-behavior: none
- touchstart で preventDefault(ボタン・メニュー以外)。ダブルタップ拡大・ピンチ・長押しメニュー・スクロールを抑止
- 入力は pointer イベント。音は最初のタッチ後に初期化
- 表示が隠れたら自動で一時停止

## 重要な操作仕様(変えないこと)
- ロック式の相対操作: 上=おす、左右=まわりこみ、下=さがる、止める=ふんばる
- 速いフリック=剣を振る(向き自由)。敵に重ねた操作は移動にならない
- 敵の「いま！」(予告の最後0.4秒)のフリック=いなす。振った直後0.5秒はいなせない
- 「おす」0.3秒以上の間は剣を振れない。きりょくゲージ(いきぎれ)あり
- 敵を押し出しても勝てない。勝敗はHP制
- 勇者の足もとは画面の上から50%。**視野は「ひろい」に決定**（`CFG` の `CAM`。切りかえの3段階とボタンはやめた。ユーザー指示 2026-11-21）
- **土俵の外に出てもダメージなし**。ふちで止まるだけ（`clampArena`。ばがいダメージ・硬直・復帰はやめた）
- **敵のターゲット表示はなし**（頭上の「A▶まほう」・ねらい線・「ねらわれた！」などの文字・下の窓の「▶ゆうしゃ」）。ターゲットの中身（ヘイトでの切りかえ）は今のまま動いている。ヘイトのゲージ（下の窓）は残してある
- 「てきが せまってくる」の表示はなし
- 勇者の頭上の行動の吹き出し（「ふんばる」「おす」など）はなし。右上の「ロック: てきA」もなし（ロックの仕組みは動いている。きりょくゲージと「いきぎれ」は残してある）
- 上のウィンドウは右上のボタンで隠せる

## 描画の現状
- 勇者・まほうつかい・敵: ローポリの箱モデル(drawHero / drawAlly / drawEnemy)。向きは連続角度(yaw)
- 床・背景: Canvas 2D の手続き描画(夜の遺跡の闘技場)
- ダメージ数字・名前・HPバー: Canvas上に重ねて描く

## WebGL化（進め方）
0. ロジックを ES モジュールに分ける（描画は Canvas 2D のまま）… 済み
1. 床・カメラ（キャラは仮の円柱）… 済み（`src/render3d.js`・`src/three-chars.js`。`?r=2d` で移行元の描画、`?fps=1` でフレームレート表示）
2. 勇者 … 済み（`three-chars.js` の `BoxModel`。移行元の `heroParts` の部品リストから、毎フレーム 面のメッシュ1つと ふちの太い線（`LineSegments2`、太さ 0.032 は世界の長さ）1つを作る。キャラ1人あたり描画2回）
3. まほうつかい・敵・止めの演出 … 済み（`allyParts` / `enemyParts` から同じ `BoxModel` で描く。ふちの線の太さはモデルの大きさに合わせる。止めの演出は移行元と同じく画面の座標（px）で動くので、画面の座標の平行投影カメラ（`ortho`）で描き、移行元と同じ 0.38 のかたむきを付ける。浮かぶ文字は WebGL の上の HUD に描くので、飛んでいく敵より手前に出る（移行元とのちがい）)
4. 背景・仕上げ … 背景は済み（実測は下の「実測」）。最適化は実機の数字を見てから
5. ボットで移行前と比べる

将来（今回はやらない）: glTF モデル化、床・背景の画像素材、コマンド選択（設計書 §3）

## 実測（段階4の時点。この作業環境は GPU なしのソフトウェア描画なので、フレームレートは目安にならない）
- 描画の回数: 1フレーム約 21 回（`WebGLRenderingContext` の draw 呼び出しを数えた）
