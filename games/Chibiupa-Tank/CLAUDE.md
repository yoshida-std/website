# ちびうぱのエサキャッチ！（`games/Chibiupa-Tank/`）

スマホ横画面・スクロールなしの固定画面。水そうの中をちびうぱが泳ぎ、上から落ちてくる人工エサをキャッチする。公開URL（まだポートフォリオには載せていない）: `https://yoshida-std.github.io/website/games/Chibiupa-Tank/`
リポジトリ全体の作業ルールはルートの `CLAUDE.md` を参照。

プッシュ前の確認用 Artifact: `https://claude.ai/artifact/VCdowGubUF6gCxXRSAujKH`（変更のたびにこの URL を更新する。`index.html` と `img/chibiupa.png` `img/logo.png` `img/side/side1〜5.gif` `sound/bgm.mp3` を同じパスで載せる）

## 仕様
- 世界は高さ400固定、幅は水槽の枠（`#stage`）の比（1.1〜2.4）に合わせて 440〜960。左右にボタン用の余白（`--rl` `--rr`）を取り、水槽は中央に寄せてボタンと重ならない。砂の上 `FLOOR=H-38`。水槽（`tankFor(stage)` の `{L,R,WT}`）はステージごとに大きさがちがい、`TL` `TR` `WATER` がいまの水槽の左右・水面。**ステージ5の水槽＝全幅**（高さは全ステージ同じ）。上の空きにHUDとふりかけ容器が入る
- **ゲームパッド**（`pollPad`。Gamepad API、標準配置のコントローラー。毎フレーム `loop` から読む）: スティック左右（デッドゾーン0.3、傾けた分だけ速い）／十字キー左右＝よこ、A・B・RB・RT＝およぐ（押しっぱなしの連続ひとかきも同じ）、X・Y・LB＝うんち、START＝ポーズ（ポーズ中は START・A・B でつづける）。**メニューは十字キー／スティックでボタンを選ぶ**: 開いているメニュー（`menuContainer`: ランキング＞せつめい＞タイトル＞ゲームオーバー＞ポーズ＞ステージ開始の順）の `button` のうち1つに黄色い光る枠（`.padfocus`）が付く。最初は主ボタン（ピンク）。十字キー／スティックを倒すと、押した方向にあるボタンのうち一番近いものへ（`moveFocus`。まず45度以内、なければ斜めも）。A＝選んでいるボタンを押す（`click()`）、B＝もどる（ランキング・せつめいは閉じる、ポーズはつづける、ゲームオーバーはタイトルへ）、START＝ステージ開始カードのスタート／ポーズのつづける。ショートカット: タイトルは X＝とことん・Y＝ランキング・BACK＝せつめい、ゲームオーバーは Y＝ランキング、ランキング画面は LB／RB でタブ切り替え。 メニューで使ったボタンはゲームの操作にしない。つながるとタイトルに「ゲームパッド OK！」と出る。ブラウザの仕様で、つないだあとにボタンをどれか1回押すまで認識されない。実機のコントローラーでは未確認（テストは `navigator.getGamepads` を差し替えて行った）。説明（`#help`）にも書いてある
- **シェア**（ゲームオーバー／クリアの画面の「📤 けっかを シェア」。`shareResult`）: ゲーム画面（`<canvas id="cv">`、Canvas 2D）の画像＋スコア＋ハッシュタグ＋URLをまとめてSNSへ。設定は `SHARE` 定数（タイトル・ハッシュタグ・文面テンプレート `{title}（{mode}）で{score}{unit}を獲得しました！{extra}`・単位・ファイル名・URL `window.location.href`・画像サイズ1200×630）。画像は `composeResultImage` が裏の Canvas に「ゲーム画面＋ロゴ＋SCORE＋モード＋順位」を合成してPNGにする（結果画面が出たときに `prepareShareImage` で先に作っておき、ボタンを押した瞬間に共有シートを開けるようにしている＝iOSのユーザー操作の制限対策）。① `navigator.canShare({files})`（ダミーの File で同期判定 `canShareFiles`）が true なら `navigator.share({files,text,url})`。キャンセル（`AbortError`）は何も出さない。それ以外の失敗は②へ。② 非対応（PC・LINE/Xのアプリ内ブラウザなど）は、ボタンを押した直後の同じ処理の中で X の投稿画面（`twitter.com/intent/tweet?text&hashtags&url`）を別タブで開き（あとからだとポップアップブロックされる）、画像を `#shareModal` に出して「長押しで保存」「画像を保存」「Xで投稿」。長押し保存のため `#shareImg` だけ `-webkit-touch-callout`・選択・`contextmenu` を許している。WebGL の画面を撮るときの黒画面対策はコードのコメント参照（`preserveDrawingBuffer:true`、またはレンダリング直後の同じタスクで撮る）。Playwright では、共有シート対応・キャンセル・失敗・非対応の4通りを `navigator.share` の差し替えで確認。**実機の共有シートは未確認**
- **左右の余白のアニメ**: タイトル以外では水槽が中央に寄って左右に余白（`--rl` `--rr`）ができるので、そこに `#sideL` `#sideR`（`<div>`、背景画像 `img/side/side1〜5.gif`、`pointer-events:none`。ボタンの後ろ）を置く。GIFは縦長のシート（スタンプ6体が2列×3段。どのコマでも体がマスの境目をまたがないことを確認済み）なので、**背景のサイズを200%×300%にして1マスだけ見せる**（`showCell`: 左上→右上→左中→右中→左下→右下の順）。ゲーム開始・ステージが変わるたび（`startStage` → `rollSides`）に、**左右ちがうシートをランダムに**選び、始めのマスもランダム。**一定時間（`SIDE_MS=3200`ms）ごとに次のマスへ、スライドのように**切り替える（右から少しすべって入る `.flip` の0.5秒アニメ）。右は半周期（1.6秒）ずらして、左右が同時に変わらないようにする。タイトル中（水槽が横いっぱい）は出さない（画像も読まない）。切り欠き（ノッチ）の分は `env(safe-area-inset-*)` でよける。**ボタンと重ならない**ように、左は ◀ ▶ の上まで、右は💩と「およぐ」の上まで（ステージ1は💩がないので「およぐ」の上まで）に収める。**左右は同じ大きさ**（CSS変数 `--sw`: 左右それぞれの「余白の幅」と「ボタンの上までの高さ」から入る大きさを `min()` で出して、いちばん小さいものを両方に使う。高さは `100dvh`（なければ `100vh`）、1マスの縦横比は 190:225.33（高さ換算の係数 .8432）、上から8px、余白の中で横に中央寄せ。ボタンの上の限界は `--botL`/`--botR`）
- **左の余白のロゴ**: 左の余白の、アニメGIFの下から ◀ ▶ ボタンの上までの空きに、タイトルと同じロゴ（`img/logo.png`）を `#sideLogo` で置く（余白の幅いっぱいに、縦は空きに収まる大きさ。`object-fit:contain`、`pointer-events:none`）。位置と高さは `--sw`・`--botL` から計算するので、GIFの大きさやボタンの大きさが変われば追従する。タイトル中は出さない
- **モード**（`mode`）: タイトルの「ステージ」＝ステージ制（`'stage'`）、「とことん」＝`'toko'`。`startGame('stage'|'toko')`。タイトルのデモは常に `'stage'`
- **とことん**: ステージ5の水槽（幅も高さも）で、どれだけ食べられるかをきそう。クリアなし。5つ消えるとおしまい（水のにごり・おなか・うんち・スポイト・ヌマエビはステージ5と同じ。`stage=5` 扱いなのでスポイト・ヌマエビは最初から出る）。**ポンプは食べた数でとちゅうから増える**: `TOKO_PUMP_AT=[25,60,100]` 個で1台ずつ、位置は `TOKO_PUMP_X=[.5,.22,.78]`（`tokoPumps`。`addTokoPump` が「ポンプ！」のバナー・あわ・音を出す）。難しさ `level()` は `floor(食べた/5)+floor(消えた×.4)`（最大14）、エサの間隔の下限0.8秒。HUDは「たべた／ベスト／エサ」
- **ランキング**: ステージ・とことんで別々、各10位まで、この端末の `localStorage`（`chibiupa_rank_stage` / `chibiupa_rank_toko`。`[{s:たべた数,st:到達ステージ,w:全クリア,t:時刻}]`。点が高い順、同点は到達ステージが先、さらに同じなら先に出したほうが上）。0個は載らない。`gameOver` で記録し（`addRank`）、ゲームオーバー／クリアのウィンドウ（`showOver`）で**ランクインなら演出**: 「ランクイン！ n位」（1位は「🏆 1位！ しんきろく！」と大きく金色）がポンと出て、紙ふぶき（`confetti`、1位は多め）とファンファーレ（`sfx.rank`）。タイトルの「ランキング」ボタンとゲームオーバー画面の「ランキング」ボタンで `#rank`（半透明のウィンドウ、ステージ／とことんのタブ、今回の記録は黄色く点滅、閉じると元の画面へ）。以前の `chibiupa_best` は使わなくなった（ベストはランキングの1位）
- **全10ステージ**（`stage`、`STAGES=10`）。クリア条件は `GOALS=[12,16,20,25,30,32,35,38,41,45]` 個（エサ1・ヌマエビ3 で数える `stageEaten`。HUDの「あと」）。水槽の幅は `TW=[.62,.72,.82,.91,1]`、水の深さは全ステージ `TH=.89`（深さの基準は H−96=304。ステージ4の高さに固定、水面は y≈129）で、**幅だけ**ステージ1→5へだんだん大きくなる。**水槽の大きさが変わるのは5ステージ目まで**（ステージ6〜10は5と同じ大きさ。`tankFor` は `min(n,5)`）。ステージ6以降はクリア条件（とポンプ）が変わるだけ。**新しい水槽に入るたびに、にごり（`lost`）・おなか・エサ・うんち・ヌマエビ・スポイトはリセット**（きれいな水）。得点 `eaten` は通しで数える（ベスト対象）。ステージ10をクリアすると「ぜんぶ クリア！」（`gameOver(true)`）
- **ステージの始まり**（カードは半透明で、後ろのゲーム画面が見える）: 演出（網が上がりきる）が終わってから、`ready` 状態で「ステージ n／エサを N こ たべよう！／ひとこと（`STAGE_NOTE`）」のカードと「スタート」ボタンを出し、**タップするまでエサは落ちない**（ウパは自動でゆらゆら泳ぐ）。ステージ1もタイトルの「あそぶ」のあとに同じカードが出る。Enter / Space でも開始。`startPlay` で `play` に入り、エサ出しは1.2秒後から
- **ポンプ**（ステージ6〜）: `PUMP_X`（水槽の幅に対する割合）の位置に置く。6:1台、7:1台（別の位置）、8:2台、9:2台、10:3台。ポンプの真上に幅±`PUMP_HW=34`の水流（`flowAt(x,y)`：中心ほど強く、約1.8秒周期で少しゆらぐ。水面より上と砂の下には出ない）。ウパは水流の中で上向き約130px/sに引かれ（`vy` を目標へ近づける）、横の動きには抵抗がかかる（`vx` を毎秒 2.4×流れの強さ だけ減らす）。エサ・うんち・ヌマエビ（沈んでいる最中）は沈む速さから `155×流れ` を引かれ、強いところでは**上へ流され**、水面でとまる。底に落ちて待っているエサ・うんちもポンプの近く（流れ>0.4）なら**ふき上げられる**（4秒のカウントは沈み直すと止まる）。ポンプの絵と上へ流れるすじ・あわは `drawPump`
- ステージ1は、💩ボタンを隠し（`body[data-stage="1"]`）、ヌマエビ・スポイトは出ない（`stage>=2` から）
- ステージ移動の演出（`startTrans` → `updateTrans`、状態 `trans`）: `clear`（「ステージ クリア！」、エサは消える、1秒）→ `scoop`（網が上から下りてきて水面で水しぶき、1.1秒）→ `lift`（網でウパをすくって水面の上へ、1秒）→ `slide`（古い水槽が左へ、新しい水槽が右からスライド、網はウパごと新しい水槽の真ん中の上へ、1.7秒）→ `lower`（網をおろして水に入れる、水しぶき、0.9秒）→ `release`（`startStage` で新ステージ開始、ウパを放す、網は上へ引きあげる `net.rising`、「ステージ n」のバナー）。この間は操作できない・ポーズできない。描画は `drawTankBack`/`drawTankFront`（水槽ごと・横ずらし付き）と `drawNet`
- 操作（スーパーマリオの水中風）: 左下 ◀ ▶ で横移動（慣性あり、最大150px/s）、右下「およぐ」でひとかき（上向き速度 −165）。放っておくとゆっくり沈む（重力260、終端85）。長押しは 0.25 秒後から 0.3 秒ごとにひとかき。キーボード: ←→/AD、Space/↑/W、Esc でポーズ
- エサ: 上のふりかけ容器が動いて落とす → 空中 `air` → 水面 `float`（1.3〜2.3秒、レベルで短く）→ ふらふら沈む `sink`（速度 24〜34 + レベル×2.4、横ゆれ）→ 砂に着く `rest`（砂の中の深さは0〜6px。4.4秒、レベルで最短2.8秒。周りの輪で残り時間、最後の1.3秒は点滅）→ 消えたら「にげられ」
- 5つ消えるとゲームオーバー。1つ消えるごとに `dirtTarget = lost/5` で水が緑茶色に濁り、ゴミ粒が増える
- レベル = `round((stage−1)×1.2) + floor((stageEaten + 消えた×2)/5)`（最大12）。上がるほど落とす間隔が短く（2.6→1.0秒）、レベル3以上で2個同時もある
- 演出: およぐ・横に進むと体が後ろに傾き、足をバタつかせてうでをかく（`P.swim` `P.ph`）。エサが80px以内に近づくと口をあーんと開け（`P.near`）、食べると0.55秒、にっこり目で口をもぐもぐ（`P.munch`。元の目と口の上を肌色でぬって描きかえる `drawFace`）
- 食べる判定: 空中以外は口（`P.y+4`）から半径27px。砂の上の `rest` は横±32px・縦±30px と広め（底のエサが取れない不具合の対策。ちびうぱが底に座ると `y=FLOOR-14`）
- おなか・うんち: エサを食べるたび `P.stomach++`（最大 `FULL=10`）。10でおなかいっぱい＝動きがにぶる（横の最高速 150→80、ひとかきの勢い 165→118で間隔1.4倍、沈むのが速い、体が少しふくらむ）。右の💩ボタン（またはキー P/S/↓）でうんち（おなか1以上で押せる。おなかが0になり、にぶいのも治る）。ボタンの輪がおなかの量、満タンで赤く点滅
- うんちはエサと同じように沈み、砂に着いて `POOP_REST=4` 秒たつと消えて **エサ2つ分のにごり**（`miss(q,2)`、5つ消失でゲームオーバー）。食べられない
- スポイト: 約5〜9秒おき（最初は9秒後）に左右どちらかの水面から入り、水深の45〜62%のところで8.5秒とまって戻る（同時に1本）。先の半径58px（点線の輪）に入ったうんちを引きよせ、13px以内で吸いとる（にごりなし、「きれい！」）。おなか5以上のときは輪の上に💩を出す
- ヌマエビは**エサよりうんちを優先**して食べに行く（底にうんちがあれば、エサをねらっていても乗りかえる。うんちが無いときだけエサ）
- ヌマエビ（生きエサ）: エサを2つ以上食べたあと、エサ出しのたびに20%で、エサの代わりにヌマエビを落とす（容器が「ヌマエビ！」と出す）。**場に出るのは最大4匹**（`MAX_SHRIMP`）（落下待ち・容器の中も数える）。落ちかたはエサと同じ（空中→水面→沈む）が、底に着くと `walk` になり**消えない**。底を歩き回り（22px/s）、砂の上の `rest` のエサ**とうんち**があれば一番近いものへ向かい（42px/s、他のエビが狙っているものは避ける）、近づくと食べる（0.7秒もぐもぐ。エサ・うんちは消えるが**にごりにならない**）。プレイヤーが食べると +3点・おなか+2（食べる判定はエサと同じ。砂の上は横±32px・縦±30px）。ゲームオーバーまで残る
- **タイトル画面**: 背景はゲームのデモ（`setupDemo`: いちばん大きいステージ5の水槽で、ウパが自動でエサやヌマエビを追いかけて食べる `updatePlayer(dt,true)`。エサ出しも動く）。デモ中は音なし・にごりや失敗なし（`miss` は見た目だけ、おなかは常に0）。デモの水槽は**画面の横いっぱい**（タイトル中だけ `#stage` の左右の余白をなくす。`setState` が `title` との出入りで `resize()` する。そのため `startGame` は `setState('ready')` のあとに `resetGame()`）。**ウィンドウなし**で、デモ画面の上にロゴ（`img/logo.png`）と「あそぶ」「せつめい」ボタンをじかに置き、コピーライトは**画面中央の下**に固定（`#title .copy`）。ゲームの説明は「せつめい」ボタンで半透明の `#help` ウィンドウに出る（開いている間はタイトルのカードを隠す。「とじる」か外側のタップで閉じる）。`toTitle` でもデモに戻る
- ウィンドウ（ステージ開始 `#ready`・ポーズ `#pause`・ゲームオーバー／クリア `#over`）は、後ろのゲーム画面が見えるよう半透明（背景の暗幕なし、カードの背景は約38%）で、文字も小さめ（見出し18px・本文10px・ボタン12.5px）。説明 `#help` も同じ半透明（タイトルはウィンドウなし）
- **ホーム画面から起動したとき**ポーズボタンが押せない不具合の対策: 画面の上のふち近く（上から6px）のタップは、iOSのスタンドアロンではシステムのジェスチャーに先に取られることがあるので、HUDとポーズボタンを上から26pxに下げ（`--edge:20px`）、ポーズボタンの押せる範囲を見た目より10pxずつ広げた（`#pauseBtn::before`）。回転後の大きさのずれ対策として `orientationchange` でも `resize` し、縦向き判定は `matchMedia('(orientation:portrait)')`。**実機のホーム画面起動では未確認**（この環境では再現できない）
- **画面の大きさの測り方**（ホーム画面から起動したとき、iPhone（ノッチあり）でタイトルのデモが拡大して見える報告の対策。**実機では未確認**）: `resize()` は `#stage` の枠だけでなく `innerWidth/innerHeight` と `visualViewport` の小さいほうを使い、見えている範囲より大きくならないようにする。`viewKey()` が変わったら（起動直後や回転後に取得値がずれる対策）、16フレームごとの確認・`orientationchange`（150ms・600ms後）・`visualViewport` の resize でも測り直す。`visualViewport.scale≠1` のときは `fixZoom()` でviewportのmetaを一瞬変えて拡大をリセット
