# たいじろうやん！ — 作業引き継ぎメモ

最終更新: 2026-10-26。ユーザーはスマホ縦画面専用のレトロ風ブラウザゲームを個人で制作中。やりとりは日本語。

## 1. 概要と操作
- プーヤン風のシューティング。主人公は猫の「たいじろう」。三角屋根のゴンドラに乗り、どんぐりを撃つ。うんち（💩）を投げることもできる。
- 敵は風船・パラシュートで上下する犬。ステージ10（FINAL）のラスボスわんこを倒すとクリア。
- タイトル表記: 「たいじろうやん！」、クレジット「©YoshidaStudio, ©PANICPUMPKIN」（タイトル画面と一時停止画面）。
- 論理幅360固定、高さは画面に合わせて可変。スマホ縦専用で、横向きにすると回転ガード（`#rotate`）が出る。
- スマホ操作: 左下のスライダー（`#slider`/`#thumb`）でゴンドラを上下。スライダー上をタップするとどんぐりを撃つ。うんちは `#bomb` ボタン。
- キーボード（開発用）: ↑↓/W/S で移動、Space/Z で射撃、X でうんち。
- メニュー: 一時停止ボタン（つづける／タイトルへもどる）、ミュート、ガイドON（どんぐりとうんちの軌道を薄いラインで表示）。
- 難易度: 「やさしい」「ふつう」。ハイスコアは別々に保存。

## 2. 決めた仕様
- 数値: 残機5、どんぐり最大16発（袋を取ると補充）、うんち最大3個（ステージクリアごとに1個回復）、`FINAL = 10`、`HUD_H = 44`。
- どんぐり: 敵本体に当たると押し戻す（画面外には出さない）。当て続けると敵が怒る（やさしい: 5/8/12回で段階的）。
- うんち: 重力で弧を描いて落ちる。貫通する。風船・パラシュート・敵に当たり判定があるが、ボスわんこの本体には無効。
- 敵の風船は最大3個。敵の骨は1本ずつ弧を描いてプレイヤーへ投げる。ゴンドラの屋根に当たると跳ね返る。
- 被弾・ゲームオーバー時はゴンドラから落ちる演出。
- ステージ構成: 奇数ステージは敵が上から下りる（パラシュート。個数が少ないほど速く落ちる）、偶数ステージは下から上へ。偶数では敵が画面左下から歩いて来る（子猫を抱えない）。その後、風船で上昇する。
- 敵の数: `quota = min(6 + 2n, 24)`。ステージ3以降は最後の1体がボス（一回り大きい）。ステージ2以降は中ボス（ひと回り大きいわんこ）と爆弾が出る。ステージ10の最後はラスボス（風船12個）。
- 爆弾: 風船/パラシュートを割って地面に落ちると爆発し、画面内の敵を一掃する。連鎖扱い。
- スコア: 風船 +100。連鎖は +200×(連鎖数-1)。大きい敵は +300、連鎖時は 300+200×(連鎖数-1)。ステージクリアでボーナス。「れんさ！」「おおきい！」の表示は大きめ。
- やさしいモードの調整: 骨の当たり判定を小さく、投げ種類の割合変更、予告フレーム40、無敵210フレーム、袋の取得範囲28、どんぐりと風船の当たり半径14、ラスボスの風船12個・待機2体、クリア時に残機+1。連鎖の当たり範囲は広め。
- 音: BGM は AAC（m4a）を WebAudio でループ（`BGM_VOL=0.24`）、ゲームオーバーのジングルは1回再生（ゲーム状態が `over` になったとき）、効果音は WebAudio 合成（`SFX_GAIN=2.4`、`beep()`）。ミュート時はBGMを止める。
- 保存（localStorage）: `ponpoko-hi`、`ponpoko-hi-easy`、`ponpoko-mode`、`ponpoko-guide`。
- ダブルタップ・ピンチ拡大・長押しメニューの防止: viewport meta（`user-scalable=no`）、`touch-action`、gesture イベントの抑止、キーボードのズーム抑止。公開後にユーザーが実機で困った項目なので、触るときは注意。

## 3. ファイル構成
- ゲーム本体（これだけが本体。画像・音もbase64で埋め込み済み）: `ponpoko-balloon.html`（約780KB）。公開版は claude.ai のアーティファクト（https://claude.ai/artifact/VvfHf1zJ5drrPqGfm5G8wy、v22）。ユーザーは同じHTMLを自分のGitHub Pages（yoshida-std.github.io 配下）にも置いている。差し替えはユーザーが行う。
  - `<head>`: タイトル、viewport、テーマ変数、フォント（DotGothic16）。
  - DOM: `#rotate`、`canvas#game`、`.controls`（ミュート、ガイド、一時停止、`#dock` の `#bomb` と `#slider`）、`#titleMenu`（やさしい/ふつう）、`#pauseMenu`。
  - `<script type="application/octet-stream" id="bgmB64">` と `id="overB64"`: BGM と ジングルのbase64。実行されないデータ用。
  - 最後に通常の `<script>`: ズーム抑止のIIFEと、ゲーム全体のIIFE（ES5風、1ファイル）。
  - 猫スプライトはdata URLでコード内に埋め込み（`spr.src`、`SPR_S=1.1`）。
- 作業ディレクトリ（セッション限り）: `/tmp/claude-0/-home-claude/f2270772-713e-5a87-a2f0-f752b462eb01/scratchpad`。セッションが終わると消えるので、次回はアーティファクトを `action: "read"` で取得して作業を始める。
- 元素材（ユーザー提供、セッション限り）: 猫のスプライトPNG、BGMのWAV、ジングルのWAV。

## 4. 検証の方法（実機なしで確認する手順）
- スクリプトを取り出して `node --check`。
- node上で document/canvas/AudioContext をモックし、キー入力を送るボットで全ステージを動かす（残機と弾を毎回リセットするチートを使う）。
- この方法では実機の挙動（タッチ、音、拡大防止）は確認できない。変更後は、ユーザーが実機で確かめる前提で伝える。

## 5. 未完成・既知の問題
- 画面収録でゲーム音が壊れる件は解決済み: 画面収録のマイクをONにして録画すれば音が入る。ゲーム側の対応は不要。
- `navigator.audioSession.type = 'playback'` は `audioCtx()` で設定したまま。消音スイッチ対策として残している。
- 実機で確認できていない点が多い（難易度、タッチ操作、音量バランス）。
- GitHub Pages側のHTMLが最新版（v22）に差し替わっているかは未確認。

## 6. やらないと決めたこと
- 画面収録用の「録画モード」や、録画のための音声まわりの追加対応は作らない（廃止済み、復活させない）。
- ステージの上限は10で、ラスボスで終了。ステージの追加や無限モードは作らない。
- 横画面対応はしない（縦専用）。

## 7. 作業の進め方（ユーザーの希望）

- 変更後は構文チェックとモックのスモークテストを行い、実機未確認であることを伝える。
