# ホリホリ・ロボバスター ファミコン版(`games/Horihori-Robo/famicom/`)

ブラウザ版(`../index.html`、仕様は `../CLAUDE.md`)を、ファミコン実機で動くROMに移植したもの。
NROM(マッパー0)、PRG 32KB + CHR 8KB、縦ミラー、電池つきPRG-RAM 8KB($6000。ハイスコア用)。EverDrive N8 で実機確認する前提。
実機ではまだ確認していない(エミュレータ jsnes でのみ確認)。

## ビルド

- 必要なもの: cc65(ca65/ld65)、Python3 + Pillow。cc65 が無い環境では `git clone https://github.com/cc65/cc65 && make bin` で作れる(`Makefile` の `CC65_BIN` で場所を指定)
- `make` → `build/horihori.nes`(と `build/horihori.lbl`=変数のアドレス表)
- `assets/` は生成物。`tools/make_assets.py`(絵・背景・迷路の表)と `tools/make_sound.py`(BGM・効果音・音程表)が作る。`../robo.png`(ブラウザ版のスプライトシート)から16x16・3色のドット絵に自動変換している(**仮の絵**。手描きに差し替える予定)

## 遊び方

- 十字キー=歩く(マス単位。途中で逆向きに戻れる)/ A=向いている先に穴を掘る・もう一度でうめる(自動ねらいは無い)/ B=ハシゴ(壁に向かって止まってから1.5秒以内。1ステージ3本)/ Start=開始・次へ・ポーズ
- 画面の上の32pxは黒地の表示帯(スコア・残機・ストップウォッチの残り秒・ステージ・金塊の数・残りのハシゴ)。その下の208px(13マス)が迷路の窓。下から上へ強制スクロール。一番上の出口(チェッカー)でステージクリア。全5ステージ
- 穴(約5.5秒)に落ちたロボは約3.5秒で這い出る。頭を踏む+200、ふさがってつぶれる+300(赤は+1000)。金塊10個(各+300、全部でPERFECT+3000)、ストップウォッチ(スクロール10秒停止)、赤いロボ(スクロールが止まると下から1体)
- ステージの始まり: ゲーム画面の上に「STAGE x」を黒い四角の中に3秒出して止まる(`intro`。その間は動かず、終わると BGM と一緒に開始)。出口に着くと黒いクリア画面(`enter_clear`。見出し・ボーナス・金塊 x/10・PERFECT!・LIFE RECOVER +1・SCORE・点滅する PUSH START)。Start で次のステージ。ステージクリアの画面では黄色いロボが左から右へ歩いて抜けていく(くり返し)。5面のあとは ALL CLEAR(RANK S/A/B/C・金塊の合計・SCORE。真ん中で黄色いロボが正面を向いて飛び跳ねる。演出は `draw_cscene`、スプライトのみ)
- ポーズ: プレイ中に Start。ゲームが止まり、画面の中央に黒い四角のコマンドウィンドウ(RESUME=再開 / RETIRE=わざとミス(残機-1) / TITLE=タイトルへ)。上下で選び、A で決定(Start でも再開)。BGM も止まる。ステージ開始の「STAGE x」の間・クリア画面・ゲームオーバーでは出せない
- ミスは3回まで。クリアで残機+1(上限3)。ミス後は復活位置の近く(3マス以内)のロボだけ3秒いなくなる

## 構成

- `src/main.s` … 全部(ca65)。主な部分: リセット/メインループ/NMI、`start_game`(1ステージの初期化)、迷路生成(`gen_maze`。growing tree、RAM上13x31)、背景行の読み込み(`build_row`。画面の上端に来たマス行だけをネームテーブルに書く)、主人公(`update_hero`。マス単位)、穴(`do_dig` `update_holes`)、ロボ(`robot_one` `robot_choose`)、距離マップ(`bfs_step`。主人公から幅優先、1フレーム24マスずつ)、音(`sound_update`)、描画(`draw_all`)
- メモリ: ゼロページに変数、`$0200` OAM、BSS に迷路 `mapram`(1行16バイト×32行、値: 0=床 1=壁 2=穴 3=ゴール 4=ハシゴ 5=金塊)・距離マップ `dist`・ロボの配列・キューなど。CHR は前半=背景(床・壁・穴・ゴール・金塊・ハシゴ)、後半=スプライト(キャラ16x16×6コマ、文字・数字、ストップウォッチ)
- 画面の作り: 縦ミラーで、画面A(`$2000`)=迷路の輪(240px=15マス行。世界のyを240で割った余りの位置に書く)、画面B(`$2400`)=表示帯。毎フレーム、NMIが画面Bのスクロール(0,0)で始め、メインループが `do_split` でスプライト0(OAM 0番。表示帯の区切り線=31行目に重ねる)の当たりを待って、迷路の窓のスクロール(0,カメラ%240)へ切り替える。表示帯の数字は `update_hud`(変わったものだけ `hudflag`)→NMIの `write_hud` で書く。表示帯の背景タイルは背景パレット1(黒地に白)
- 座標: 画面のy=世界のy-カメラ+32(`w2s`)。窓の外(カメラから208px以上)は隠す。下辺は窓の下端(`check_squeeze` の193)
- スプライトOAM: 0〜3 スプライト0 / 4〜19 主人公 / 20〜115 ロボ(0〜4=白、5=赤) / 116〜235 文字(PUSH START・GAME OVER・STAGE x。文字の絵が黒地なので、スプライトで「黒い四角の中の白い文字」になる。上下の余白の行も黒い空白スプライト(タイル49)。1行は8個まで) / 236〜251 ストップウォッチ本体
- クリア画面は背景(画面B $2400)に作る。タイル52〜77=A〜Z、78='!'、79='+'、80='/'。文字は `.charmap` で書く(`.repeat` で書くとうまく変換されなかったので1行ずつ)。行ごとの色は `assets/resattr.bin`(背景パレット1=白、3=黄、2=PUSH STARTの点滅。NMIで `$3F0A` を切り替える)。迷路の画面(画面A)は触らない(次のステージの `start_game` が作り直す)
- ポーズのウィンドウはスプライト(OAM 4〜143。35個=7個x5行)。若い番号が手前・優先なので、`enter_pause` で主人公・ロボのスプライト(OAM 4〜115)を OAM 144〜255 へずらしてから前に書く。`leave_pause` で全部消して `draw_all` で描き直す。ボタンの「押した瞬間」は `padnew`
- タイトル画面: 黒地。上の32pxは画面B(HIGH SCORE。静的)、その下の208pxに、ゲームの壁のブロックの枠に囲まれた大きなタイトル「HORIHORI / ROBO BUSTER」(黄色、赤い影)、白・黄(主人公)・赤の3体のロボ(スプライト)、点滅する PUSH START、©表記。絵(`assets/titlepic.bin`=13マス行x64バイト+属性64)は迷路と同じスクロールの仕組みで、上から1フレーム2pxで降りてくる(`tcam` 208→0。マス行が上端に出るたび `build_trow` →NMIで書く。表示帯の下のスプライト0で切り替え)。ロボは同じ速さで一緒に降りる。背景色は黒に変える(`show_title`)ので、ゲームを始めるとき `start_game` が戻す。PUSH START の点滅はクリア画面と同じ(背景パレット2の色2をNMIで切り替え)
- ハイスコア: `hsr`(5桁)。`update_hi` が、ステージクリア(クリア画面に入るとき)・ゲームオーバー・ポーズの TITLE で、スコアが大きければ更新して `$6000` の電池つきRAMに保存(`'H' 'R'`・5桁・検査値。壊れていれば0から)。RAMが無いカートでも動く(その電源の間だけ覚える)。EverDrive N8 でセーブが残るかは実機未確認。ゲームオーバーのあとの Start はタイトルを通らず、そのまま最初から
- BGM: ブラウザ版の曲(PANICPUMPKIN「ちんけなくらし」。テンポ100、60小節、約144秒でループ)を `tools/transcribe_bgm.py` で**自動採譜**した2声(メロディ=矩形波1、ベース=三角波)。結果は `assets/bgm_notes.json`(16分音符=9フレームの格子。ビルドにはこれだけあればよい)。ドラムと和音は拾っていないので、原曲とは違う。曲の利用・加工は PANICPUMPKIN さんのサイトで自由と表記されているのを確認済み(ユーザー確認)。タイトル画面に「©2026 YOSHIDASTUDIO」「©PANICPUMPKIN」を出している。`assets/bgm_notes.json` が無いときは仮の曲になる
- 乱数は16bit LFSR。種は「Startを押すまでのフレーム数」

## 確認ツール(`tools/`、jsnes が必要: `git clone https://github.com/bfirsh/jsnes /tmp/jsnes`)

- `node tools/run_headless.mjs build/horihori.nes 出力prefix "start:2,wait:200,up:30,poke=名前;オフセット;値"` … 環境変数 `SYMS=変数名,...`(値を表示)、`DUMP=mapram:496`(RAMを書き出す)、`VRAM=2AC5,...`(PPUのメモリ)、`AUDIO=out.wav`(音を書き出す)。画面は `出力prefix_s番号_キー.rgb`(256x240のRGB)
- `node tools/soak_test.mjs build/horihori.nes 30000 種` … ランダム入力の長時間テスト(止まらないか、値がおかしくならないか)
- `node tools/bot_test.mjs build/horihori.nes 40000 [1]` … 迷路をたどるボットで5面まで通す(1を付けると残機固定)

## ブラウザ版との違い・まだ無いもの

- 迷路の長さは全ステージ31行(ブラウザ版は14〜30)。3x3の部屋、出口前の壁の行は無い
- 赤いロボ登場の演出画像、ガイド表示、クリア画面への HIGH SCORE の表示、BGMのドラムと和音、ミス・クリアのアニメ、クリアでの BGM の続きからの再開(次のステージは毎回頭から)、ハシゴ上のキャラのコマ、ストップウォッチの浮遊アニメ、タイトルロゴ
- 絵は自動変換のため粗い。手描きのドット絵(16x16・3色+透明)に差し替える
