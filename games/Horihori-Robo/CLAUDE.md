# ホリホリ・ロボバスター（`games/Horihori-Robo/`）

スマホ縦画面向けの縦スクロール穴ほりアクション（仮題。名前・フォルダ名は変えてよい）。公開URL: `https://yoshida-std.github.io/website/games/Horihori-Robo/`
リポジトリ全体の作業ルール（ブランチ・PR・確認方法・コピーライト表記）はルートの `CLAUDE.md` を参照。

プッシュ前の確認用 Artifact: `https://claude.ai/artifact/1JWDnmdpVxVJC3r7oNmZKN`（変更のたびにこの URL を更新する。`index.html` 1枚だけ載せる。Artifact には `<!doctype>`・`<html>`・`<head>`・`<body>` のタグを除いた写しを公開する）

`index.html` 1枚で完結（音は WebAudio の合成、画像なし）。`games.json`（ポートフォリオの一覧）にはまだ載せていない。

## 概要と操作

- ファミコンのボンバーマン風の迷路（幅13マス）。**画面は強制的に上へスクロール**し、下に押しつぶされる前に上のゴール行（白黒のチェッカー）へ着けばステージクリア。無限にステージが続く
- 左下のスティックで4方向に移動、右下の「ホル」ボタン（**スティックの円盤・ポーズボタン以外の画面のどこをタップしても同じ**。片手で遊べるように。`digIds` で押している指を数える）で穴をほる（ロードランナー式）。**自動ねらい**: 歩いて5マス以内（`AIM_RANGE`。プレイヤーを起点にした BFS の距離 `flow` で測る）に、画面内で動いているロボがいれば、そのロボの来る道すじの最後の1マス（プレイヤーのとなり）にほる（ロボが真横にいればそのマス）。いなければ **向いている方の1マス先**。ねらった方向をむく。ハシゴは「向いている方向が壁のとき」だけ（ロボが近いときはロボを優先）。0.5秒以上の長押しで連続（ふつうのタップが少し長くなっても2回ほらない）。走りながらでも、次のマスの境目でほる（ボタン入力は0.4秒ためておく）。向いた先に穴があれば、もう一度「タップ」すると埋める（押しっぱなしでは埋めない。押しっぱなしは新しい穴を連続でほるだけ）（トラップ中のロボごとつぶす +300）。ロボが立っているマスにもほれる（その場で穴に落ちる）。キーボード: 矢印/WASD、Space/Z/X、P でポーズ
- 穴は約5.5秒でふさがる（終わり際に点滅して縮む）。白いロボは穴に落ちて「トラップ」状態（約3〜4秒で這い出る）。**トラップ中のロボの頭は踏んで渡れる**（初回 +200）。穴がふさがるとロボはつぶれる（+300）
- **ハシゴ**: 壁（外周とゴール行より上は除く）に向かってホルボタンを「タップ」すると、その壁のマスにハシゴがかかり、通れるようになる（ロボも通る。グリッド値 2）。1ステージに3つ（HUD の「ハシゴ」）。押しっぱなしでは置かない。ハシゴのマスには穴はほれない
- **金塊の山**: 1ステージに10か所（`GOLD_N`）。迷路の高さを10に分けた帯ごとに1つずつ、ランダムな床に置く（`placeGold`）。触れると +300（`GOLD_PTS`）。ステージ内で10個ぜんぶ取ってゴールすると「PERFECT!」ボーナス +3000（`PERFECT_PTS`）。画面の下に流れたものは取れない。HUD の「金」に取った数
- プレイヤーも穴に落ちる（約1秒で這い出る。その間にふさがる・ロボにさわられるとミス）
- ミスの条件: ロボにさわる／画面の下に押しつぶされる／穴に埋まる。**ミスは3回まで**（3回目でゲームオーバー）。ミス後は画面中ほどの近くで復活し、2.5秒の無敵
- スコア: ロボ踏み 200、つぶす 300、金塊 300、前進 1マス 10、クリア 1000＋残りライフ×500、パーフェクト 3000。ベストは `localStorage` の `horihori_best`

## 実装メモ

- 迷路: セル 6×R（R = min(16+3n, 32)）を growing tree（新しい方/ランダムを半々）で掘り、15% の壁を抜き、3×3 の部屋（中央に柱）を足す。最上段は全部あけたゴール行、最下段は柱つきのスタート部屋。偶数×偶数の柱は壁のまま
- 生成後に最短経路を調べ、「プレイヤー速度 2.8マス/秒、2.2秒の猶予」でスクロールに追いつけるか確認して、だめなら作り直す（40回まで）
- スクロール速度 `min(2.0, 0.95+0.12n)` マス/秒。プレイヤーが上から 40% より上にいるときは 2.4 倍で追いかける
- ロボ: 全部で `MAX_ROBOTS`=5 体（画面にいるのは最大5体）。迷路には置かない。ステージ開始時は5体とも画面の上の「ロボ待機」の帯に一列に並び、2秒後から1.4秒ずつずらして出てくる。やられたロボ（つぶされた・画面の下に落ちた・復活のときに近くにいて消された）は帯の最後尾に並び、`respawnDelay()`＝`max(4, 7.5-0.4n)` 秒たつと、先頭のロボが帯の上をすべって迷路の上端の空いたマスに降りてくる。残りは1つずつ前に詰める（`updQueue`）。各ロボの下の緑の棒が復活までの進み具合で、あと0.9秒で目が点滅して跳ねる。スクロールが上端に着いてゴールが近い（`camY<3`）間は出てこない。プレイヤーを起点にした BFS の距離を下るので穴を避けない。ほかのロボが歩いているマスには入らず行列になる。速度 `min(2.6, 1.6+0.15n)`（プレイヤーの 3.9 よりだいぶ遅い）
- 移動はマス単位のなめらかな歩み（`advance`）。歩きの途中で逆向きには即座に戻れる
- 見た目は「斜め上から」の2.5D（ボンバーマン風の明るい配色: 砂色・黄緑の床、オレンジのレンガ壁、青いHUD）。床を全部描いたあと、行ごとに壁（上面を `WALL_H`=0.3マス分持ち上げて前面を描く）→その行のロボ・プレイヤーの順に描いて隠れ方を作る。キャラは `y+0.38` を中心に描く（マスより少し上）
- 穴の見た目・ロボの絵・プレイヤーの絵はすべて canvas の矩形描画（デバイスピクセル単位で `S`＝1マスのpx）
- プレイヤーの歩く速さは `PSPD`=3.9マス/秒。ミス・ステージ開始のとき、ホルボタンの入力（`digReq` `digFresh` `digHeld`）を捨てる。`play` 以外の状態で押したホルボタンは無視する（死んだ直後のタップで復活後に掘れてしまう不具合の対策）
- デバッグ用に `window.__dbg`（状態の参照）がある。消してよい

## 確認のしかた

`python3 -m http.server` で配信し、Playwright（iPhone 13 / SE）で開く。`__dbg` から `pl`・`ens`・`holes` を直接書き換えると、穴に落とす・踏む・ふさがる、などの場面を作れる。
