# ホリホリ・ロボバスター（`games/Horihori-Robo/`）

スマホ縦画面向けの縦スクロール穴ほりアクション（仮題。名前・フォルダ名は変えてよい）。公開URL: `https://yoshida-std.github.io/website/games/Horihori-Robo/`
リポジトリ全体の作業ルール（ブランチ・PR・確認方法・コピーライト表記）はルートの `CLAUDE.md` を参照。

プッシュ前の確認用 Artifact: `https://claude.ai/artifact/1JWDnmdpVxVJC3r7oNmZKN`（変更のたびにこの URL を更新する。`index.html` 1枚だけ載せる。Artifact には `<!doctype>`・`<html>`・`<head>`・`<body>` のタグを除いた写しを公開する）

`index.html` 1枚で完結（音は WebAudio の合成、画像なし）。`games.json`（ポートフォリオの一覧）にはまだ載せていない。

## 概要と操作

- ファミコンのボンバーマン風の迷路（幅13マス）。**画面は強制的に上へスクロール**し、下に押しつぶされる前に上のゴール行（白黒のチェッカー）へ着けばステージクリア。無限にステージが続く
- 左下のスティックで4方向に移動、右下の「ホル」ボタンで **向いている方の1マス先** に穴をほる（ロードランナー式）。長押しで連続。走りながらでも、次のマスの境目でほる（ボタン入力は0.4秒ためておく）。向いた先に穴があれば、もう一度「タップ」すると埋める（押しっぱなしでは埋めない。押しっぱなしは新しい穴を連続でほるだけ）（トラップ中のロボごとつぶす +300）。ロボが立っているマスにもほれる（その場で穴に落ちる）。キーボード: 矢印/WASD、Space/Z/X、P でポーズ
- 穴は約5.5秒でふさがる（終わり際に点滅して縮む）。白いロボは穴に落ちて「トラップ」状態（約3〜4秒で這い出る）。**トラップ中のロボの頭は踏んで渡れる**（初回 +200）。穴がふさがるとロボはつぶれる（+300）
- **ハシゴ**: 壁（外周とゴール行より上は除く）に向かってホルボタンを「タップ」すると、その壁のマスにハシゴがかかり、通れるようになる（ロボも通る。グリッド値 2）。1ステージに3つ（HUD の「ハシゴ」）。押しっぱなしでは置かない。ハシゴのマスには穴はほれない
- プレイヤーも穴に落ちる（約1秒で這い出る。その間にふさがる・ロボにさわられるとミス）
- ミスの条件: ロボにさわる／画面の下に押しつぶされる／穴に埋まる。**ミスは3回まで**（3回目でゲームオーバー）。ミス後は画面中ほどの近くで復活し、2.5秒の無敵
- スコア: ロボ踏み 200、つぶす 300、前進 1マス 10、クリア 1000＋残りライフ×500。ベストは `localStorage` の `horihori_best`

## 実装メモ

- 迷路: セル 6×R（R = min(16+3n, 32)）を growing tree（新しい方/ランダムを半々）で掘り、15% の壁を抜き、3×3 の部屋（中央に柱）を足す。最上段は全部あけたゴール行、最下段は柱つきのスタート部屋。偶数×偶数の柱は壁のまま
- 生成後に最短経路を調べ、「プレイヤー速度 3.3マス/秒、2.2秒の猶予」でスクロールに追いつけるか確認して、だめなら作り直す（40回まで）
- スクロール速度 `min(2.0, 0.95+0.12n)` マス/秒。プレイヤーが上から 40% より上にいるときは 2.4 倍で追いかける
- ロボ: 迷路には置かず、画面の上の外から1体ずつ出す（間隔 `max(0.7, 1.5-0.1n)` 秒）。**生きているロボは最大5体**（`MAX_ROBOTS`。画面の外へ出たものも数える）。プレイヤーを起点にした BFS の距離を下るので穴を避けない。ほかのロボが歩いているマスには入らず行列になる。速度 `min(3.4, 2.1+0.25n)`
- 移動はマス単位のなめらかな歩み（`advance`）。歩きの途中で逆向きには即座に戻れる
- 穴の見た目・ロボの絵・プレイヤーの絵はすべて canvas の矩形描画（デバイスピクセル単位で `S`＝1マスのpx）
- デバッグ用に `window.__dbg`（状態の参照）がある。消してよい

## 確認のしかた

`python3 -m http.server` で配信し、Playwright（iPhone 13 / SE）で開く。`__dbg` から `pl`・`ens`・`holes` を直接書き換えると、穴に落とす・踏む・ふさがる、などの場面を作れる。
