# 天使と悪魔のジャッジ2（`games/judge2/`）

スマホ横置きの対戦ゲーム。前作（judge1）は `https://yoshida-std.github.io/judge/`（リポジトリ `yoshida-std/yoshida-std.github.io` の `judge/`）。
公開URL: `https://yoshida-std.github.io/website/games/judge2/`
リポジトリ全体の作業ルール（ブランチ・PR・確認方法・コピーライト表記）はルートの `CLAUDE.md` を参照。

プッシュ前の確認用 Artifact: `https://claude.ai/artifact/T7NEiNKBu6RVnbtYoi7CQT`（変更のたびにこの URL を更新する。`index.html` と画像・`manifest.json`・`sound/bgm086.mp3` を同じパスで載せる）

## 概要と操作

- 左右のパネルが P1（天使）と P2（悪魔）の操作。それぞれ「たたく」「さける」。PC ではキーボード（P1: A/S、P2: K/L）
- ラウンド開始から 1〜2.5 秒後に、両者の札に 0〜99 の数字が出る
  - 数字が大きいほう（同じなら両方）は **たたく** が正解。相手に当てるとハンマーのダメージ分ライフが減る
  - 小さいほうは **さける** が正解（セーフで次のラウンド）
  - 間違えると自分が 1 ダメージ（からぶり・よけミス）。数字が出る前に押すと「おてつき」で 1 ダメージ
  - 先に押したほうだけが判定される。3.5 秒だれも押さなければ「じかんぎれ」で次のラウンド
- ライフは 6。ハンマーはラウンドごとに抽選（×1: 60%、×2: 30%、×3: 10%）
- モード: ふたりで / CPU（よわい・ふつう・つよい）。CPU は P2 側

## 決めた仕様

**CPU**（`LV`）: 数字が出てから反応するまでの時間、行動を間違える確率、おてつきする確率

| 強さ | 反応(ms) | 間違い | おてつき |
|---|---|---|---|
| よわい | 650〜1100 | 22% | 5% |
| ふつう | 430〜760 | 10% | 2% |
| つよい | 300〜480 | 4% | 0% |

**スマッシュ演出**（たたいて当たったとき、`smash`）
1. ため: ハンマーを振りかぶって小刻みに震え、キラッと光る
2. 踏みこみ＋スイング: 相手の頭にハンマーの頭が届く位置までジャンプして振り下ろす（振りの軌跡を描く）
3. インパクト: ヒットストップ（200+90×ダメージ ms、とどめは 600ms）。最初の約 0.1 秒は白黒反転のインパクトフレーム、白フラッシュ、集中線、ヒットの火花・衝撃波リング・星、画面揺れ、カメラが当たった点へズーム、×2 以上は「SMASH!」の文字
4. ふっとび: 回転しながら煙を引いて画面の外へ → 上から落ちてきて戻る
- とどめ（`finish`）: スローモーション＋青い背景の集中線でやられた側にズーム → 場外へふっとび → 画面のふちから光の爆発 → 「GAME SET」→ 結果画面
- からぶり・よけミス・おてつきで負けたときは、倒れてから「GAME SET」

**時間の仕組み**: 演出は自前のトゥイーン（`tw`）と `sleep` で書いていて、ゲーム内時間で進む。`hitstop` の間は止まり、`timeScale` でスローになる。タイトルへ戻ると `G.seq` が変わって、進行中の演出はすべて止まる

**ライフ表示**: ハートは SVG で描く（文字の ❤ は iPhone で絵文字になり、色を変えられず減ったように見えなかった）。操作ボタンの文字は横書き

**結果画面**: 勝ったキャラの絵を手前、「WIN!」の文字を後ろに重ねる（`#rimg` の z-index を `#rlogo` より上にする）

**音**
- BGM は BGM086。試合の最初（キャラが出てくるところ）から「GAME SET」まで流しっぱなしでループ。「GAME SET」で 0.4 秒かけて消す。タイトル・結果画面は無音
- 数字の札が出てからそのラウンドが終わるまで（次のラウンドが始まるまで）は BGM を小さくする（通常 `BGM_VOL`=0.42 → `BGM_LOW`=0.12）
- MP3 の末尾の無音をループに含めないよう、元の WAV の長さ `BGM_LEN=33.488` を `loopEnd` にしている
- 効果音は WebAudio の合成音（`SFX`）。`AudioContext` は最初のボタン操作で作る

## ファイル構成と役割

```
games/judge2/
├── CLAUDE.md          … このファイル
├── index.html         … ゲーム本体（HTML / CSS / JS をすべて含む）
├── manifest.json      … ホーム画面に追加したとき横向き・全画面にする
├── icon-192.png       … ホーム画面のアイコン
├── sound/bgm086.mp3  … ゲーム中BGM（元: BGM086-100610-aozorashakarikisawagi.wav, 33.5秒。元の WAV はリポジトリに入れない）
├── cloud_bg.jpg       … 背景（judge1 の cloud_bg.png を JPEG にしたもの）
├── player1.svg / player2.svg / player1_win.svg / player2_win.svg
├── hammer1.svg / hammer2.svg / hammer3.svg   … ダメージ ×1 / ×2 / ×3
└── title_logo.svg / title_player.svg / win.svg
```
画像は judge1 からそのまま持ってきた。

`index.html` 内の主な区分（`/* ---------- ... ---------- */` のコメントで区切っている）
- ブラウザ動作の抑止 / 音（`SFX`）/ レイアウト（`layout`, `pivot`, `headAt`）
- 時間とトゥイーン（`tw`, `sleep`, `freeze`）/ カメラ（`camS`, `zoomTo`, `shake`）
- エフェクト（canvas 3枚: `fxbg` はキャラの後ろ、`fxw` はキャラの前でカメラと一緒に動く、`fxs` は画面に固定）
- メインループ `frame` / ゲーム状態（`G`, `startRound`, `reveal`, `action`）/ 各アクション（`smash`, `finish`, `whiff`, `dodgeSafe`, `dodgeMiss`, `penalty`）/ 入力

## 未完成のところ・既知のバグ

- **実機で未確認**: 演出の重さ（インパクトフレームで大きな SVG に filter をかけている）、CPU の強さのバランス
- 演出中に画面サイズが変わると、ふっとび中のキャラの位置が少しずれる
- 「キャラが画面の外に出てしまった」という報告あり（実機、どの場面かは未確認）。対策として、毎フレーム画面の大きさを確かめて変わっていたら `layout()` し直す、ラウンドの始めに2人を定位置に戻す、を入れた
- 音の ON/OFF は保存していない
- BGM のループのつなぎ目は実機で未確認（Safari で小さな切れ目が出るかも）
